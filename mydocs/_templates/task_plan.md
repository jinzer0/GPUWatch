# 수행계획서 템플릿

이 파일은 `mydocs/plans/task_{milestone_slug}_{issue}.md` 작성용 중앙 템플릿이다. 수행계획서는 작업 목적, 범위, 설계 방향, 검증 기준을 기록한다. 작은 작업은 기존 이슈/작업 맥락 기록을 사용하며 중복 계획서를 만들지 않는다.

위험 분류와 승인 범위는 [공유 위험 정책](../manual/agent_code_hyperfall_rule_conflict.md)을 따른다. LOW는 즉시, 명확히 요청된 MEDIUM 범위는 계획·구현·검증·보고·다음 단계까지 자동 진행한다. HIGH는 해당 위험 결정만 승인받고 정확한 결정과 근거를 기록한다. 독립적인 안전 작업은 계속한다. 도구 권한과 명시적 커밋 허가는 별도로 유지하며 계획서 커밋을 안전한 구현의 필수 조건으로 삼지 않는다.

## 문서 위치 판단

이번 task에서 제품/사용자/기여자/외부 통합/API/아키텍처/로드맵 문서를 생성, 이동, 수정한다면 공식 문서 루트와 `mydocs/` 중 어느 위치를 사용할지 먼저 판단한다. 문서 변경이 없으면 `해당 없음`과 이유를 적는다.

Hyper-Waterfall은 공식 문서 루트 이름을 고정하지 않는다. 대상 프로젝트가 `docs/`, `specs/`, `site/`, `website/`, `adr/`, `book/`, GitHub Wiki 등을 명시적으로 선택할 수 있으며 선택 이유와 위험 판단을 기록한다. HIGH에 해당하는 위치 결정만 정확한 결정에 대한 승인을 받는다.
