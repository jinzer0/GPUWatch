## 설계 방향

- 런타임은 React renderer → action-specific Electron preload/IPC → 로컬 Rust helper → core → fixed no-install SSH → SQLite를 유지한다. `contextIsolation: true`, `nodeIntegration: false`, Electron main의 수집 스케줄링을 보존한다.
- 가용 카드 상태와 알림 opt-in을 분리한다. 실패·unknown·stale에는 현재 `사용 가능` 강조나 새 알림을 만들지 않는다. 단일 0%, 미터의 초록 구간, 프로세스 없음은 가용 판정 근거가 아니다.
- 가용의 지속 관측 정보는 신뢰 가능한 백엔드 상태로 제공한다. renderer에서 별도 타이머나 프로세스 수로 추정하지 않는다. 기존 DTO에 필요한 상태가 없는 경우 core/read-model/helper 계약을 최소 확장하는 방안을 구현계획에서 구체화한다.
- 기존 알림 재활성화의 null 임계값 전송과 규칙 변경 시 지속·마지막 알림 시각 초기화를 점검한다. 기존 사용자 조건 보존과 반복 방지 계약을 충족하도록 필요한 수정·회귀 검증을 포함한다.
- OS 알림 허용 여부를 알 수 없으면 확인 불가로 표현한다. 가짜 허용/거부·권한 요청 성공을 만들지 않는다. 시스템 설정의 알림·집중 모드 확인 경로를 안내한다.
- 미터 구간은 UTIL/VRAM ≤30% 낮음, >30–≤60% 중간, >60% 높음; 온도 ≤60°C 낮음, >60–≤80°C 중간, >80°C 높음이다. 승인된 노랑은 라이트 `#F2D000`, 다크 `#FFE14A`이며 장식 채움에만 사용한다. 정확한 값·단위·구간 텍스트를 유지한다.
- 20칸·2px 간격·8px 높이 및 온도 길이 0–100°C는 잠정 기준이다. 온도 채움 길이만 제한하고 숫자·색 판정은 실제 °C로 한다. unknown을 0으로 치환하지 않는다.
- 초기 시스템 테마, 마지막 유효 서버 재선택, 세션 내 서버별 펼침 보존·재실행 시 접힘, 미저장 변경 시 계속 편집/변경 버리기를 잠정 기준으로 삼는다.
- 실제 macOS 타이틀바·드래그 영역·별도 창 수명·VoiceOver·최소 창 크기는 Electron 실행으로 검증한다. HTML 확인만으로 완료를 주장하지 않는다.
- 기존 데이터·테스트 패턴을 재사용하되 제거된 화면의 dead routing/UI 코드는 남기지 않는다. 의존성 추가는 기존 의존성의 한계를 확인한 경우에만 별도 판단한다.

- **Stage 4 — 가용 알림 연결과 통합 인계**

### 단계별 검증

- Stage 1: Shell·설정 창·테마 store 및 action-specific IPC 테스트, `npm run build`, `npm run electron:build`. macOS 메뉴/`⌘,`/아이콘이 같은 창에 도달하고 설정 창을 닫아도 메인 창·스케줄러가 유지되는 시나리오.
- Stage 2: GPU detail·process focused Vitest, 30/60%·60/80°C의 양쪽 경계, 실제 0과 null·총량 불가, stale 성공 시각, 중첩 키보드 토글·다중 펼침·긴 문자열 확인.
- Stage 3: settings/controller/import focused Vitest와 IPC 테스트. 추가·편집·삭제 취소·실패, 모니터링 전환 실패, SSH 테스트 실패, 후보 제외·부분 저장 결과, 미저장 보호·포커스 복귀 시나리오.
- Stage 4: core/helper 가용 관측·조건 보존·반복 방지 테스트와 Electron scheduler/notifications 테스트. 299/300초 및 899/900초 경계, 연속 유휴 중 1회, 재사용 후 재준비, 실패/unknown/stale 중 새 강조·알림 없음, 알림 off여도 카드 표시를 독립 확인.

### 통합 검증

- `npm run helper:build` 후 `npm run test -- --run`, `npm run build`, `npm run electron:build`.
- `cargo test --manifest-path crates/gpuwatcher-core/Cargo.toml`, `cargo test --manifest-path crates/gpuwatcher-helper/Cargo.toml`.
- 격리된 테스트 DB·예시/fake helper 기반 UI smoke로 서버 중심 여정·관리·설정·다중 펼침을 확인. 기존 smoke가 새 탐색과 맞지 않으면 수정 후 실행한다.
- `npm run smoke:electron:first-run`. 필요 시 `npm run electron:pack` 후 `node smoke/electron-packaged-app-smoke.mjs`로 unsigned 로컬 패키지의 별도 설정 창·리소스 경로 확인.
- 일반 검증은 live SSH·실제 사용 서버·운영 DB를 사용하지 않는다. 실제 OS 알림 확인이 필요하면 별도 승인된 격리 시나리오로 제한하며 알림 권한·집중 모드로 인한 노출 한계를 보고한다.
- plain Vite에서는 실제 Electron bridge 부재를 backend_unavailable로 유지하고 서버 조작 성공·가용 데이터를 만들어내지 않는다.
- 라이트·다크·시스템 테마, VoiceOver/키보드, 드래그 영역, 본문/표 스크롤, 최소 창 크기·텍스트 확대를 실제 앱에서 확인한다. HTML 시안 검증과 앱 검증 결과를 분리한다.
- 최종 수용 기준은 승인된 계약과 Issue #29의 포함/제외 범위를 모두 충족하는 것이다.
- `git diff --check`에 경고가 없고 PR 준비 전 `git status --short`가 빈 출력이어야 한다. 임의 stash/삭제로 사용자 변경을 숨기지 않는다.

위 명령은 향후 검증 계획이다. 이번 문서 작성 단계에서 앱 테스트·빌드·실제 SSH·OS 알림을 실행했다는 뜻이 아니다.

## 리스크

- **설계 입력 분리**: 최종 계약은 기본 worktree의 미커밋 파일이다. 원본을 보존하고 승인된 위치에 필요한 파일만 검증해 복사한다. 계획 작성 중 원본·제품 문서는 변경하지 않는다.
- **가용 상태와 opt-in 결합**: 현재 watch runtime 정보만으로 알림 off인 GPU의 가용 표시까지 해결된다고 가정하면 잘못된 표시가 생긴다. 백엔드 상태 노출·DTO·관측 재설정 책임을 구현계획에서 명시한다.
- **사용자 조건/반복 방지 초기화**: 재활성화·규칙 저장이 기존 조건이나 cooldown 이력을 초기화할 수 있다. 상태 전이와 보존 회귀 테스트로 계약을 입증한다.
- **창·외형 통합**: 새 설정 창이 scheduler/renderer 초기화를 중복 실행하거나 보안 경계를 넓힐 수 있다. 창 역할별 초기화와 IPC 허용 목록을 검증한다.
- **정보 손실**: 전역 화면 제거 과정에서 프로세스·추가 지표·관리 기능을 잃지 않도록 기존 기능과 새 표면을 대조한다. backend API·저장 정책 삭제는 하지 않는다.
- **시안 밖 상태**: 로딩·빈 상태·일부 오류·미저장 보호는 계약 전용이다. 해당 상태를 구현 테스트·격리 시나리오에 포함한다.
- **격리 worktree 의존성**: node_modules·helper debug 바이너리가 없을 수 있다. 테스트 전 준비하고 누락 때문에 실패한 테스트를 억제하거나 통과한 것으로 보고하지 않는다.
- **기준 브랜치 차이**: main에 병합된 Dependabot 변경과 devel의 동기화는 별도 작업이다. 이 task에서 임의 merge·cherry-pick하지 않는다.
- **승인·커밋 경계**: 이번 승인은 문서 작성뿐이다. task-start의 문서 커밋 관례가 있더라도 명시적 커밋 승인을 받기 전 staging·commit·push를 하지 않는다.
