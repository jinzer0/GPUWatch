## 설계 방향

1. **기존 Electron Builder를 중심으로 구성한다.** 기존 의존성의 signing·extra binary·notarization 기능과 Apple codesign/notarytool/stapler/spctl을 사용한다. 자체 서명·공증 프로토콜이나 중복 인증 저장소를 만들지 않는다.
2. **signed/unsigned 경계를 명시한다.** 기존 dev·unsigned 명령은 내부 테스트용으로 유지하고 새 signed 명령만 외부 배포 후보를 만든다. signed 경로에서 identity/credential/Accepted/ticket 검증이 누락되면 실패한다. ad-hoc/unsigned fallback·warn-only 성공은 금지한다.
3. **자격증명·대상을 실행 시 고정한다.** 실제 Developer ID identity/Team ID는 구현 검증 시 확인해 승인된 실행 입력에 결박한다. repository에는 개인 인증서 이름·키 파일을 기본값으로 넣지 않는다. 공증 인증은 `APPLE_KEYCHAIN_PROFILE`과 Keychain을 사용한다. 다른 credential environment가 profile보다 우선되는 상태는 명시적으로 검사해 차단한다.
4. **helper도 load-bearing 서명 대상이다.** Electron/framework/helper를 실제 포함된 파일 기준으로 서명·검증한다. contextIsolation/nodeIntegration·action-specific preload·helper 위치와 stdout envelope 계약은 바꾸지 않는다. 검증 통과를 위해 필요 이상의 entitlement나 전역 library validation 해제를 추가하지 않는다.
5. **검증 단계의 원격 부작용을 분리한다.** Stage 1 설정·mock 테스트는 Apple 업로드를 하지 않는다. Stage 2 Apple 제출은 승인된 제품 commit·배포 대상·Keychain profile·signed app/DMG hash·제출 행위를 별도 exact 실행 입력으로 결박한 후 수행한다. 인증 조회는 read-only 근거로 별도 기록한다.
6. **산출물은 한 번의 빌드 lineage에 결박한다.** 코드 commit·version/arch·signature Team ID·공증 request ID/Accepted·staple/Gatekeeper 결과·DMG/ZIP hash와 변경 시각을 manifest/evidence에 남긴다. staple 등 바이트 변경 전후 hash를 구분하고 ZIP은 검증된 stapled app으로 만든다. 이전 파일 재사용이나 stale 성공 receipt를 금지한다.
7. **검증과 발행은 다르다.** 실제 Gatekeeper·공증·package smoke 통과 전에는 외부 배포 준비 완료로 표현하지 않는다. 통과해도 GitHub Release에 asset이 업로드된 상태로 표현하지 않는다. 기존 unsigned v0.1.0 설치 안내의 역사적 사실은 보존한다.

### 단계별 검증

- Stage 1: focused Vitest/config tests, version/lockfile 대조, `npm run build`, `npm run electron:build`, `npm run helper:build`, 기존 unsigned gate, `git diff --check`.

## 리스크

- **인증/권한**: profile 인증 성공은 signing private key 접근이나 App 공증 수락 보장이 아니다. Keychain prompt·Apple network·심사 실패는 blocker로 기록하고 unsigned로 우회하지 않는다.
- **native notarization 건너뛰기**: 설치 dependency는 missing credential이면 warn-only skip할 수 있다. 입력 검증과 실제 Accepted/ticket/Gatekeeper의 사후 검증을 필수로 한다.
- **실행 권한/entitlement**: Electron JIT와 별도 Rust helper에 과도한 entitlement를 복제하지 않는다. 필요한 최소 설정과 포함 binary 서명을 검증한다.
- **검증 비용**: 공증 제출은 Apple 네트워크·시간을 사용한다. 무한 retry나 이전 Accepted 재사용 없이 실패 원문과 정확한 artifact를 보존한다.
- **stale artifact·혼용**: signed/unsigned 출력과 receipt를 분리하고 시각·hash·commit을 결박한다. 실제 app 경로는 탐색하며 mac/mac-arm64를 가정하지 않는다.
- **발행 상태**: v0.1.0 Release가 이미 존재한다. 기존 tag/asset 덮어쓰기나 아직 없는 v0.2.0 Release 링크를 만들지 않는다.
- **사용자 작업**: 분리 worktree에서만 작업하고 원 worktree/BMad·main worktree·기존 backup branch와 증거를 건드리지 않는다.
