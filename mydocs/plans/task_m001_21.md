# Task #21 수행계획서 — Task: Process Table을 GPU 사용 현황 핵심 화면으로 승격

GitHub Issue: [#21](https://github.com/jinzer0/GPUWatch/issues/21)
마일스톤: M001

## 목적

Process Table을 GPU 사용 원인 분석의 핵심 화면으로 승격한다. GPU/PID/User/Process/GPU 사용률/VRAM 중심 정보 계층과 스캔성을 개선하되 destructive process action은 추가하지 않는다.

## 배경

GPU 모니터링에서 가장 중요한 질문은 누가 GPU와 VRAM을 점유하는지다. 현재 Process Table은 기능적으로 존재하지만 디자인 리팩토링에서는 Apple Activity Monitor 같은 sortable table 감각과 GPU Activity Monitor식 정보 밀도를 강화해야 한다.

## 범위

### 포함

- `src/features/processes/*` 화면, toolbar, row table, drawer 연계 개선
- `src/styles/tables.css` 스타일 보정
- Process Table 관련 테스트 갱신
- filter/sort/empty/error/backend unavailable 상태 유지

### 제외

- Shell navigation/toolbar 변경
- Overview KPI 재구성
- backend/helper contract 변경
- 프로세스 kill, SSH 명령 실행, destructive action 추가

## 설계 방향

- GPU 점유 원인을 빠르게 찾도록 GPU, PID, User, Process, GPU %, VRAM을 우선 배치한다.
- Compact density에서도 정보가 뭉개지지 않게 table spacing과 badge hierarchy를 조정한다.
- row action은 조회/복사/상세 확인 수준으로 제한하고 destructive action은 배제한다.
- 접근성 테스트의 table semantics와 keyboard navigation 기대값을 유지한다.
