# Task #25 수행계획서 — Task: 디자인 리팩토링 통합 검증

GitHub Issue: [#25](https://github.com/jinzer0/GPUWatch/issues/25)
마일스톤: M001

## 목적

PR #22, #23, #24가 merge된 `devel` 통합 상태에서 Shell, Overview, Process Table 디자인 리팩토링 결과를 검증한다. focused tests, build, smoke/browser QA를 통해 통합 회귀 여부를 확인하고 발견 사항을 수정 또는 후속 이슈로 분리한다.

## 배경

세 UI 리팩토링 PR은 개별 검증과 Codex 리뷰 대응을 거쳐 merge됐다. 순차 merge 과정에서 orders 문서 충돌 해결과 publish branch 재동기화가 있었고, 최종 `devel` 기준으로 전체 UI 조합을 다시 확인해야 한다.

## 범위

### 포함

- `devel` 통합 상태 확인
- Shell navigation/toolbar 통합 검증
- Overview GPU Activity dashboard 통합 검증
- Process Table GPU activity/root-cause table 통합 검증
- focused tests, build, 필요한 Vite/Electron smoke 또는 browser QA
- 검증 결과 보고서 작성

### 제외

- 새로운 디자인 기능 추가
- backend/helper/Rust contract 변경
- signed/notarized release 작업
- PR #22-#24 범위를 벗어난 대규모 UI 재설계
- destructive process action 추가

## 설계 방향

- 검증 우선 task로 진행하며, 수정은 통합 검증에서 발견된 회귀와 smoke/test selector 불일치에 한정한다.
- backend/helper contract는 변경하지 않는다.
- 브라우저 QA는 대표 viewport와 full/compact density 중심으로 수행한다.
- 회귀 범위가 큰 경우 직접 확장하지 않고 후속 이슈 후보로 기록한다.

## 잠정 단계

- **Stage 1 — 통합 테스트와 빌드 검증**
  - 산출물: focused tests, build 결과, 발견 이슈 목록
  - 검증 관점: Shell/Overview/Process tests와 build가 최종 devel에서 통과하는지
- **Stage 2 — 브라우저/스모크 QA**
  - 산출물: Vite 또는 Electron smoke/browser QA 결과
  - 검증 관점: navigation, full/compact density, 대표 viewport에서 visible layout 사용 가능 여부
- **Stage 3 — 회귀 수정 또는 후속 분리와 최종 정리**
  - 산출물: 필요한 수정, 후속 후보, 최종 검증 증거
  - 검증 관점: 수정 후 focused/integration checks 재통과

## 검증 계획

### 단계별 검증

- Stage 1
  - `npm run test -- --run src/components/Shell.test.tsx src/features/overview/OverviewScreen.test.tsx src/features/overview/overviewModel.test.ts src/features/processes/ProcessTableScreen.test.tsx src/features/processes/ProcessTableAccessibility.test.tsx`
  - `npm run build`
- Stage 2
  - Vite browser QA 또는 Electron smoke subset
- Stage 3
  - 변경 파일별 focused test
  - `git diff --check`

### 통합 검증

- `npm run build`
- focused UI tests 통과
- browser/smoke QA 결과 기록
- `git status --short`가 PR 준비 전 빈 출력이다.
- `git diff --check`가 경고 없이 통과한다.

## 리스크

- **GUI QA 범위 확대**: smoke 전체가 오래 걸리거나 환경 의존적이면 필수 화면 subset으로 제한하고 한계를 보고한다.
- **후속 회귀 발견**: 통합 검증 범위를 넘는 수정은 후속 이슈로 분리한다.
