## Foundation

macOS Electron 데스크톱 앱의 UX 계약이다. `DESIGN.md`가 시각 정체성과 토큰을 소유하고 이 문서는 탐색·행동·상태를 소유한다. 특정 UI 라이브러리는 선택하지 않았다. Scratch는 시각 영감일 뿐이며 Electron을 유지하고 Tauri를 도입하지 않는다.

**추적 규칙:** `확인됨`은 `.memlog.md`의 decision, `[ASSUMPTION]`은 개별 확정하지 않은 가역적 잠정안이다. 사용자는 이 잠정안을 구현 인계 기준으로 유지한 채 2026-10-05 설계 최종화를 승인했다. GPU UTIL/VRAM 사용률·온도의 구간 경계, 세 지표의 분절형 표현 및 중간색 라이트 `#F2D000`·다크 `#FFE14A`는 개별 확정됐다. 온도 미터 길이 척도와 나머지 세부 수치·접근성·실패 회복 세부에는 [ASSUMPTION]을 유지한다. 로그에 기록된 개인·내부 GPU 모니터링 맥락과 가상 인물 민수는 실제 사용자 조사로 간주하지 않는다. 설계 최종화는 제품 코드 구현 승인이 아니다. 참조 시안과 충돌하면 두 계약이 우선한다.

**제품 불변조건:** unknown/null 지표는 끝까지 알 수 없는 값이며 0으로 대체하지 않는다. 수집 실패 시 마지막 성공 스냅샷과 그 성공 시각을 보존한다. 실패 시각을 성공 시각으로 덮어쓰지 않는다. History 화면 제거는 저장 정책·API 삭제 승인이 아니다. 이 설계·시안 확인에는 live SSH 접속이 필요 없으며 예시 데이터로 상태를 표현한다. SSH 설정 저장과 실제 연결 성공을 같은 결과로 취급하지 않는다.

## Information Architecture

| Surface | 진입 | 목적·범위 | 근거 |
|---|---|---|---|
| 메인 창 — 서버 사이드바 | 앱 실행, 메인 창으로 복귀 | 왼쪽에 서버 목록 항상 표시; 서버 선택과 추가·편집 진입, 하단 설정 아이콘 | 확인됨 |
| 메인 창 — 서버 본문 | 서버 선택 | 모든 GPU의 VRAM 사용량/총량(GiB)·사용률/UTIL/온도 숫자와 분절형 미터 요약; 개별 카드 제자리 상세·프로세스 펼침, 동시 펼침 허용 | 확인됨 |
| 서버 편집 시트 | 사이드바 추가·편집 | 서버 연결 정보 입력·저장·취소 | 추가·편집 진입은 확인됨; 시트 형태는 [ASSUMPTION] |
| 서버 관리 대체 상태 | 서버별 `…` 또는 사이드바 `+` | 삭제 확인, 모니터링 상태 변경, SSH 테스트 결과, SSH config 가져오기 미리보기 | 기능과 진입은 확인됨; 세부 표현은 [ASSUMPTION] |
| 별도 설정 창 | macOS 메뉴 GPUWatcher → 설정…, ⌘, 또는 사이드바 하단 설정 아이콘 | 모든 진입점이 같은 하나의 설정 창을 열며 외형 세 선택 제공 | 확인됨 |

History는 새 탐색 구조에서 제거한다. 전역 history 차트·별도 GPU 상세 페이지·프로세스 종료 조작을 추가하지 않는다.

**확인됨 — 기존 서버 관리 유지:** 서버별 `…` 메뉴에 편집·삭제·모니터링 켜기/끄기·SSH 연결 테스트를 둔다. 사이드바 `+` 메뉴에는 서버 직접 추가·SSH config 가져오기를 둔다. 메뉴 대상 서버와 현재 선택 서버를 혼동하지 않도록 한다. [ASSUMPTION] 삭제는 대상 이름을 포함한 확인 후 수행하며, 실패 시 목록을 제거하지 않는다. 메뉴는 키보드로 접근하고 Esc로 닫으면 호출 버튼으로 포커스를 돌린다.

참조 시안: [라이트](mockups/key-main-light.html)·[다크](mockups/key-main-dark.html)는 Flow 1의 동시 카드 펼침, GPU 요약 미터, stale/unknown 예시, 경계 fixture와 Flow 4의 GPU 3 가용 강조·알림 설정·앱 밖 알림 예시를 보여준다. GPU 3의 5분 지속은 설명용 이력이며 실제 관측이 아니다. 알림 설정 조작은 GPU 3에서만 대표로 보여준다. [설정 창](mockups/key-settings.html)은 Flow 3의 세 외형 선택을 보여준다. [서버 관리](mockups/key-server-management.html)는 Flow 2의 편집 시트와 삭제·모니터링·SSH 테스트·가져오기 대체 상태를 보여준다. 카드와 `추가 지표`·`…`·`+` 메뉴의 HTML 기본 펼침만 동작하며 관리·설정 저장·OS 알림·네트워크 요청은 수행하지 않는다. HTML의 메뉴 펼침은 배치 확인용이며 실제 메뉴의 Esc·화살표 이동·포커스 복원을 구현한 것은 아니다.

**[ASSUMPTION]** 마지막 서버를 재선택한다. 서버별 카드 펼침 상태는 세션 동안 유지하고 앱 재실행 시 접힌 상태로 초기화한다. 마지막 서버가 없거나 유효하지 않으면 선택 안내를 표시한다. 사이드바 폭은 `{spacing.sidebar-width}`, 본문은 한 열이며 각 카드의 `{components.GpuCard.padding}`을 따른다.

## Voice and Tone

**[ASSUMPTION]** 짧은 한국어 상태 문구를 사용하고 사실·원인·다음 행동을 분리한다. 지표 이름과 단위는 생략하지 않는다.

| 상황 | 문구 제안 | 피할 표현 |
|---|---|---|
| 서버 없음 | 서버를 추가하세요. | 연결 실패 (연결을 시도하지 않은 상태) |
| 미선택 | 왼쪽에서 서버를 선택하세요. | 빈 흰 화면 |
| 지표 unknown | 알 수 없음 | 0%, 0°C, 프로세스 없음으로 추정 |
| stale | 최신 정보를 가져오지 못했습니다. 마지막 성공: … | 지금 업데이트됨 |
| 설정 저장 | 서버 정보를 저장했습니다. | 연결되었습니다 (연결 확인 없이) |
| 권한/인증 실패 | SSH 인증을 확인하세요. | 알 수 없는 오류만 표시 |

마지막 성공 시각은 데이터의 실제 타임스탬프를 기준으로 표시한다. **[ASSUMPTION]** 로컬 시각과 시간대 정보를 접근 가능한 형태로 제공하며 상대 시간만으로 대체하지 않는다.

## Metric Bars & Classification

**확인됨 — `.memlog.md`의 decision:** GPU UTIL 및 VRAM 사용률은 `≤30%` 낮음, `>30%–≤60%` 중간, `>60%` 높음이다. 온도는 `≤60°C` 낮음, `>60°C–≤80°C` 중간, `>80°C` 높음이다. 경계는 inclusive/exclusive를 그대로 적용한다. 색과 텍스트 band는 부하·온도 구간일 뿐 오류·연결 건강·GPU 안전 한계 verdict가 아니다. 숫자와 `낮음`/`중간`/`높음` 텍스트를 항상 함께 보여 색만으로 의미를 전하지 않는다.

| 의미 | 라이트 토큰 | 다크 토큰 | 정확한 hex |
|---|---|---|---|
| 낮음 | `{colors.metric-low}` | `{colors.metric-low-dark}` | [ASSUMPTION] — `DESIGN.md` 참조 |
| 중간 | `{colors.metric-medium}` | `{colors.metric-medium-dark}` | 시안 승인됨 — 라이트 `#F2D000` / 다크 `#FFE14A` |
| 높음 | `{colors.metric-high}` | `{colors.metric-high-dark}` | [ASSUMPTION] — `DESIGN.md` 참조 |

VRAM 한 metric 안에 `사용량 / 총량 GiB`와 사용률을 함께 표시하고, 사용률에는 그 metric 하나의 미터를 둔다. **확인됨:** GPU UTIL·VRAM·온도 모두 같은 분절형 미터를 적용한다. 숫자·단위·band 텍스트와 현재 구간색 하나의 채움을 함께 표시한다. **[ASSUMPTION]** `{components.MetricBar.segments}`칸, 간격 `{components.MetricBar.gap}`, 높이 `{components.MetricBar.height}`를 사용하며 마지막 칸은 부분 채움을 허용한다. 색 구간 판정과 숫자는 칸 수로 반올림하지 않는다. HTML 시안의 미터는 `aria-hidden="true"`인 장식으로 두고 인접한 완전한 레이블·숫자·단위·band를 접근 가능한 표현으로 사용한다. 시안은 정적 증거이며 JavaScript로 band를 분류하는 구현이 아니다.

**범위 산출:** GPU UTIL 입력은 유효한 `0–100%` 값 그대로 사용률 막대 길이로 쓴다. VRAM 사용률은 사용 GiB ÷ 총 GiB × 100으로 도출하며 총량이 존재하고 양수일 때만 계산한다. 유효한 백분율의 채움 너비는 그 백분율이다. 온도 band는 실제 숫자 °C로 분류하지만 길이만 [ASSUMPTION] 척도 `0–100°C`에 맞춘다. 그 척도는 퍼센트나 하드웨어 최대 온도가 아니다. 길이는 `clamp(온도 °C, 0, 100)%`로 제한하고 표시 숫자와 band는 원래 온도를 보존해 판정한다.

**Unknown·zero·stale:** 백분율 누락/비수치/`<0`/`>100`, 사용량 누락, 또는 VRAM 총량 누락·0·음수이면 해당 미터는 분절 마스크 없이 중립 점선 track만 그리고 `data-value`와 fill은 생략한다. 인접 텍스트는 `알 수 없음`이며 이를 0 또는 초록으로 대체하지 않는다. 누락/비수치 온도도 같은 unknown 표현을 쓴다. 알려진 실제 `0`은 유효한 낮음 band이며 숫자 0과 중립색 빈 분절을 표시한다. stale 값은 마지막 성공 timestamp와 `마지막 성공 값` 표기를 유지하고 현재값처럼 표시하지 않는다. stale 미터는 band/값을 보존하되 흐리게 구분한다.

각 mock의 앱 바깥 fixture는 0/30/31/60/61/100% 및 60/61/80/81°C 경계를 명시적으로 나열한다. fixture의 `.metric-bar`는 `data-metric`, 유효 값의 `data-value`, `data-band`를 가진다. unknown은 `data-value`와 `.metric-fill` 자식을 생략한다. 온도 fixture에는 60/80°C 경계를 문구로 표시하며 모든 fixture는 정적이고 앱 동작을 가장하지 않는다.

## Component Patterns

시각 규격은 `DESIGN.md.Components`의 같은 이름을 따른다. 확인되지 않은 행동에는 `[ASSUMPTION]`을 명시했다.

| ServerSidebar | 항상 보이는 탐색 | 확인됨: 서버 선택과 추가·편집 진입, 하단 설정 진입. [ASSUMPTION] 목록 스크롤 중에도 관리 진입은 접근 가능. `{components.ServerSidebar.width}`. |
| ServerRow | 서버 선택 | 확인됨: 선택 서버의 GPU 요약을 오른쪽에 표시. [ASSUMPTION] 키보드로 선택 가능, 선택·포커스·연결 건강 상태를 구분. 선택 표현은 `{components.ServerRow.selected}` / `{components.ServerRow.selected-dark}`. |

| GpuCard | GPU 요약과 상세 | 확인됨: VRAM 사용량/총량(GiB)과 사용률, UTIL·온도 숫자/단위/band 및 MetricBar를 요약하고, 선택 시 같은 카드에서 상세·해당 GPU 프로세스를 표시. 독립 접기/펼치기, 다른 펼침 유지. 기존 추가 지표는 삭제하지 않고 카드 안의 초기 접힘 `추가 지표`에서 제공. [ASSUMPTION] 요약 헤더를 토글로 삼고 상세 텍스트 선택은 접힘을 유발하지 않음. `{components.GpuCard.radius}`. |
| AvailabilityWatch | GPU별 가용 알림 설정 | 펼친 GPU 카드 내부에서 설정하며 선택 서버와 GPU 식별자를 결박한다. 알림 on/off와 카드 강조를 분리한다. 저장 실패 시 성공으로 표시하지 않고 조작 포커스는 헤더 토글과 분리한다. `{components.AvailabilityWatch.foreground}`. |

| MetricValue | 지표 이름·값·단위·band | 제품 불변조건: unknown을 0으로 바꾸지 않음. stale 값은 마지막 성공 시각과 `마지막 성공 값` 텍스트를 함께 표시. 각 값에 `낮음`/`중간`/`높음` 또는 `알 수 없음`을 써 색에만 의존하지 않음. `{components.MetricValue.font-size}`. |
| MetricBar | 세 지표 공통 분절형 미터 | `DESIGN.md`의 light/dark `metric-low`, `metric-medium`, `metric-high` 토큰 쌍 사용. `{components.MetricBar.segments}`칸의 단색 채움, 부분 마지막 칸, 실제 값 기준 band와 인접 숫자 텍스트. 백분율 범위는 0–100; 온도 fill 길이만 [ASSUMPTION] 0–100°C 척도로 제한. unknown은 분절 없는 중립 점선 track/no fill, stale은 마지막 성공 timestamp와 함께 흐리게 표시. 시안 미터는 `aria-hidden="true"`, 높이는 `{components.MetricBar.height}`. |
| ProcessTable | 펼친 GPU의 프로세스 | 확인됨: 해당 GPU 상세 안에서 프로세스 확인. [ASSUMPTION] PID/사용자/명령/VRAM의 읽기 전용 표, 텍스트 선택·복사 가능, 수집 불가와 실제 빈 목록 구별. kill 조작 없음. `{components.ProcessTable.font-size}`. |

### GPU 가용 상태와 알림 — 승인된 규칙

- **기본 판정:** GPU UTIL ≤5% **그리고** VRAM 사용량 ≤1024MiB(1GiB)가 성공적인 관측에서 300초 지속해야 한다. 미터의 초록 구간(≤30%)이나 한 번의 낮은 값, 프로세스가 없다는 사실만으로 가용을 확정하지 않는다.
- **카드:** 조건 지속 확인 전에는 일반 카드, 충족 시 은은한 녹색 배경·테두리와 `사용 가능` 문구를 표시한다. 알림 켜기/끄기와 시각적 가용 표시는 별개다. 조건 이탈 시 일반 카드로 돌아간다.
- **데이터 불확실:** unknown·수집 실패·stale은 현재 가용으로 판정하지 않는다. 이전 성공 수치는 남겨도 `사용 가능` 강조를 유지하지 않는다. [ASSUMPTION] `가용 여부 확인 불가`와 마지막 성공 시각을 함께 표시하고 지속 판정을 재확인한다.
- **설정:** 펼친 해당 GPU 카드 안에서 `사용 가능해지면 알림`을 켜고 끈다. 기존 가용 알림 기능을 유지한다. 저장된 GPU별 사용자 규칙을 이 기본값으로 자동 덮어쓰지 않는다. 저장 조건의 읽기 전용 표시·보존과 새 임계값 편집기 제외는 수용된 이번 인계 범위다.
- **발송:** 알림을 켠 GPU가 가용 조건을 충족하면 macOS 알림을 제공한다. 계속 유휴인 동안 한 번만 알리고, 사용 상태로 돌아온 뒤 다시 300초 조건을 충족하면 재알림한다. 이전 알림 후 최소 900초 간격도 충족해야 한다. 15분마다 반복하는 타이머가 아니다.
- **경계:** 카드의 접힘·펼침이나 다른 서버 선택으로 알림 감시가 해제되지 않는다. 실제 스케줄링은 기존 Electron main 경계를 유지한다. 앱 종료·절전 중의 관측이나 OS 알림 배너 노출을 보장하지 않는다.

### 알림 세부 — 잠정안 [ASSUMPTION]

- GPU 카드의 on/off 옆에 **현재 저장된 조건**을 읽기 전용으로 표시한다. 신규 규칙에만 승인된 기본값을 사용하고 기존 규칙은 끄기·다시 켜기에서도 사용자 지정값을 보존한다. 값을 읽지 못하면 토글을 비활성화하고 `저장된 알림 설정을 읽을 수 없습니다`로 안내한다.
- 임의 임계값 편집 폼은 현재 상세 UI에 없는 별도 기능이다. 이번 잠정안은 기존 규칙 표시·보존만 포함하는 것으로 수용됐으며 새 편집기는 이번 범위에 추가하지 않는다. 향후 추가는 별도 범위 결정이고 이번 최종화의 미결정 항목이 아니다. 기존 저장 규칙 제거 승인도 아니다.
- OS 허용 여부를 실제로 알 수 없으면 `macOS 알림 허용 상태는 확인되지 않았습니다`로 표시한다. 시스템 설정 → 알림 → GPUWatcher와 집중 모드 확인 경로를 안내하며 가짜 권한 상태나 작동하지 않는 권한 요청 버튼을 추가하지 않는다. 실제 관측된 거부 상태에만 거부 안내를 쓴다.
- 실패 시 마지막 저장 상태를 유지하고 재시도 안내를 제공한다. 카드 강조·서버 수집과 OS 배너 노출은 별개이며 권한·집중 모드 때문에 배너가 보이지 않을 수 있다.
- 라이트·다크 시안의 GPU 3 안에 안내를 두고 앱 모형 밖에 사용자 지정 조건·저장 실패·읽기 실패의 독립 예시를 배치한다. 정적 예시는 실제 저장·권한 조회 결과가 아니다.

**구현 인계 주의:** 현재 `DetailGpuCard.tsx`의 다시 켜기는 임계값을 null로 보내며, `repository/watches.rs`는 변경 시 지속 관측과 마지막 알림 시각을 초기화한다. 기존 조건 보존 및 반복 방지 계약을 현재 코드가 이미 충족한다고 간주하지 않는다. Electron 알림 어댑터도 현재 OS 권한 상태를 반환하지 않는다. 가용 카드의 상태 노출과 함께 제품 구현 계획에서 확인할 사항이며 이 설계 작업에서는 소스를 수정하지 않는다.

### 추가 지표 — 승인된 정보 보존

기존 `DetailGpuCard`의 지표를 유지한다. 요약에 이미 있는 GPU UTIL·온도·VRAM 사용량/총량·점유율과 상세의 프로세스 수는 중복 나열하지 않는다. 나머지는 각 카드 내부의 기본 접힘 `추가 지표`로 접근한다. History 화면 제거는 유지하며 시계열 차트 복원이나 백엔드 저장 정책 변경을 뜻하지 않는다.

| 그룹 | 보존할 정보 |
|---|---|
| 동작 지표 | 메모리 활동률, 남은 VRAM, 소비 전력/전력 한도, 팬 속도 |
| 기능·식별 | 인코더·디코더·JPEG·OFA 사용률, GPU UUID, PCI bus ID, GPU별 드라이버 버전, 그래픽·메모리 클록 |
| PCIe | RX·TX 전송률, 현재 링크 세대·폭 |
| MIG | 현재 모드, 적용 대기 모드, 인스턴스 수, 정보 제공 여부 안내 |

**의미 구분:** 메모리 활동률(`memoryUtilizationPercent`, 원본 `utilization.memory`)은 메모리 사용량/총량으로 계산한 VRAM 점유율이 아니다. 알려지지 않은 값은 `알 수 없음`으로 남기며 미지원 팬·MIG 정보를 0이나 꺼짐으로 추정하지 않는다. stale일 때는 추가 지표에도 같은 마지막 성공 시각·상태가 적용된다.

**[ASSUMPTION] 세부 배치:** 프로세스 아래에 그룹별 읽기 전용 텍스트 목록을 두고 추가 카드나 색상 미터는 만들지 않는다. 내부 토글은 부모 카드와 다른 GPU의 펼침을 바꾸지 않는다. HTML 기본 동작으로 같은 페이지에서 다시 부모를 열 때 하위 펼침이 유지되지만 앱 재실행 복원 정책을 확정한 것은 아니다. 양쪽 테마 시안에 4개 GPU의 추가 지표가 있으며 기본값은 모두 접힘이다.

## State Patterns

아래 표현·회복 제안은 **[ASSUMPTION]**이며 unknown/stale 보존은 제품 불변조건이다. 모든 IA 표면의 해당 상태를 포함한다.

| 표면·상태 | 표시·회복 |
|---|---|
| 메인 사이드바 — cold load | 목록 로딩 표시. 아직 서버 없음으로 단정하지 않음. |
| 메인 사이드바 — empty/미선택 | 추가 진입과 안내; 미선택이면 본문에서 서버 선택 안내. |
| 메인 사이드바 — 목록 오류/로컬 백엔드 불가 | 가능한 기존 서버 이름 보존, 실패 원인과 재시도; 성공한 연결처럼 표시하지 않음. |
| 서버 본문 — 최초 로딩, 성공 스냅샷 없음 | GPU 요약 구조의 로딩 표시, 수치 0이나 임의 GPU 개수 채우기 금지. |
| 서버 본문 — 새로고침 중, 성공 스냅샷 있음 | 기존 값·펼침·마지막 성공 시각 보존, 수집 중 표시만 추가. |
| 서버 본문 — 정상/GPU 없음 | 성공한 결과의 실제 GPU 목록 표시; 실제 빈 목록일 때만 GPU 없음 안내. |
| 서버 본문 — offline/SSH 인증·접근 거부/timeout | 원인에 맞는 설명과 재시도, 사이드바 편집으로 복구 경로. 이전 성공 있으면 stale 표시와 성공 시각 보존, 없으면 데이터 없음. |
| 서버 본문 — 부분 지표 unavailable/범위 오류 | 얻은 지표는 유지. 누락 또는 유효 범위 밖 백분율과 총량 없는 VRAM은 해당 MetricValue `알 수 없음`과 중립 점선 track/no fill로 표현; 이를 0이나 낮음 band로 추정하지 않음. 부분 경고를 전체 연결 실패로 승격하지 않음. |
| 서버 본문 — stale summary | 마지막 성공 timestamp와 `마지막 성공 값`을 유지하고 bar를 흐리게 구분; stale 수치를 최신 성공처럼 보이게 하지 않음. |
| 펼친 GPU — 프로세스 empty/수집 불가 | 성공한 빈 목록은 프로세스 없음; 수집 불가는 알 수 없음과 사유. GPU 요약·다른 카드 읽기 유지. |
| 펼친 GPU — 추가 지표 접힘/일부 미제공 | 접힘은 정보 삭제가 아님. 펼치면 알려진 값과 `알 수 없음`을 구분하고, 일부 미제공이어도 요약·프로세스 읽기는 유지. |
| GPU — 유휴 후보/가용/사용 재개 | 기준 이하이나 5분 미충족은 일반 카드. 5분 확인 시 `사용 가능` 강조, 조건 이탈 시 강조 해제. 상태 변화로 카드 펼침이나 스크롤을 바꾸지 않음. |
| GPU — 가용 관측 중 실패/unknown/stale | 기존 수치는 stale로 남기되 현재 가용 강조와 새 알림은 중단. 마지막 성공 시각과 가용 확인 불가 문구. |
| GPU 알림 — 저장/권한 실패 | [ASSUMPTION] 저장 실패 시 마지막 저장 선택을 유지하고 재시도 제공. macOS 알림 권한 거부는 시스템 설정 안내, 카드의 가용 표시는 유지. 집중 모드로 배너가 안 뜬 것을 서버 장애로 표시하지 않음. |
| 메인 창 — focus/서버 전환 | 선택과 포커스 분리. 새 서버 이름과 데이터의 서버 식별이 맞을 때만 표시하여 이전 서버 값이 새 서버 값처럼 보이지 않음. |
| 서버 편집 시트 — 초기/empty/focus | 추가는 빈 입력, 편집은 저장값; 필수 필드 레이블과 최초 포커스 제공. |
| 서버 편집 시트 — 검증/저장 실패·권한 거부 | 필드 오류 또는 저장 실패 원인 표시, 입력 보존. 실제 SSH 접속이 없어도 로컬 저장 성공과 연결 상태는 구분. |
| 서버 편집 시트 — 저장 중/성공/취소 | 중복 저장 방지, 성공 후 목록 반영; 취소는 원본 유지. 삭제는 승인된 서버별 `…` 메뉴와 별도 확인으로 제공하며 편집 시트에 중복 추가하지 않음. |
| 서버 관리 — 삭제 확인/실패 | 메뉴 대상 서버 이름을 확인에 명시. 취소가 안전한 기본 조작이며 삭제 실패 시 목록을 보존. 원격 프로세스 종료가 아님을 구분. |
| 서버 관리 — 모니터링 꺼짐/변경 실패 | 꺼짐을 연결 장애나 GPU 유휴로 해석하지 않음. 변경 실패 시 마지막 저장 상태 유지. |
| 서버 관리 — SSH 테스트 중/성공/실패 | 대상 서버와 결과를 함께 표시. 로컬 저장 성공, SSH 접속 확인, GPU 수집 성공은 구분. 실패 원인과 재시도 안내. |
| 서버 관리 — 가져오기 읽기/일괄 저장 중 | `SSH config 읽는 중` 또는 `선택한 서버 저장 중`을 구분. 실행 중 중복 요청을 막고 기존 후보·선택을 보존. 완료 후 저장·건너뜀·실패 결과를 표시하며 진행 중 전체 성공으로 단정하지 않음. |
| 서버 관리 — 가져오기 빈 결과/읽기 실패/미리보기/경고/부분 실패 | 가져올 별칭 없음과 SSH config 읽기 실패를 구분. 후보를 확인·선택한 뒤 저장. 제외 사유와 경고를 표시하고 부분 실패를 전체 성공으로 표시하지 않음. 재시도에서 성공한 항목을 중복 추가하지 않는 동작은 구현 시 확인. |
| 설정 창 — 초기 로딩/값 없음 | 저장값을 읽는 동안 미확정 상태 표시. 값이 없을 때만 초기 시스템 모드 제안 적용. |
| 설정 창 — focus/선택/시스템 외형 변화 | 선택 모드 명시, 시스템 모드만 외형 변화 추종. 세 옵션 중 선택 없음처럼 보이는 빈 상태 금지. |
| 설정 창 — 저장 실패/로컬 접근 거부 | 오류 설명, 마지막 저장 선택으로 복원하고 재시도 제공. 네트워크 offline은 로컬 테마 선택을 막지 않음. |

## Interaction Primitives

- **확인됨:** 서버 선택 → 모든 GPU 요약 → 카드 제자리 펼침. 다른 카드의 펼침을 자동 해제하지 않는다.
- **확인됨:** GPUWatcher → 설정…, ⌘, 및 사이드바 설정 아이콘은 동일한 별도 창 진입이다.
- **[ASSUMPTION]** Tab은 서버 탐색→본문 조작 순서, Enter/Space는 포커스된 행·토글 실행. 펼침 후 포커스는 헤더에 유지하여 추가 펼침 비교를 돕는다.
- **[ASSUMPTION]** Esc는 서버 편집을 취소하고 설정 창을 닫는다. 미저장 입력이 있으면 `계속 편집` / `변경 버리기` 확인을 먼저 보여주며 안전한 기본 선택은 계속 편집이다. 닫기 후 호출 위치로 복귀하며 설정 창을 닫아도 메인 창은 유지한다.
- **[ASSUMPTION]** 상세 확장은 짧고 절제된 전환만 사용하고 Reduce Motion에서는 즉시 변경한다. 갱신으로 포커스나 스크롤을 강제로 이동하지 않는다.

## Accessibility Floor

아래는 모두 **[ASSUMPTION] 접근성 계약 제안**이며 아직 검증된 구현이 아니다. 시각 대비 목표는 `DESIGN.md.Colors`를 따른다.

- 모든 조작을 키보드로 수행할 수 있게 하고 명시적인 `{colors.focus}` / `{colors.focus-dark}` 포커스를 제공한다. 선택 배경만으로 포커스를 대신하지 않는다.
- VoiceOver에 서버 행의 이름·선택·연결 상태, GPU 헤더의 식별자·펼침 상태, ThemeSelector의 현재 선택을 전달한다. 토글과 내부 표 조작을 중첩된 클릭 영역으로 만들지 않는다.
- MetricBar는 장식(`aria-hidden="true"`)으로 두고 완전한 인접 텍스트(지표 이름·값·단위·band 또는 `알 수 없음`)를 제공한다. unknown에 숫자형 ARIA 값을 만들지 않는다.
- ProcessTable에는 열 머리글·GPU 연관 관계를 제공한다. unknown, 실제 0, stale 값의 성공 시각을 음성으로도 구별한다.
- 서버 편집 시트의 포커스는 시트 내부로 한정하고 닫으면 복귀한다. 설정 창 활성화 시 창 이름·현재 외형 선택에 접근할 수 있게 한다.
- 오류·수집 완료는 필요한 변화만 조용히 공지한다. 매 polling마다 값을 모두 읽거나 동일 실패를 반복 낭독하지 않는다.
- 텍스트 확대·고대비·Reduce Motion을 고려한다. `{typography.body.fontSize}`를 기본값으로 삼되 확대 시 제어·단위·명령을 숨기지 않는다. 작은 아이콘의 실제 히트 영역은 시안에서 확인한다.

## Responsive & Platform

확인됨: macOS 데스크톱이며 항상 보이는 서버 사이드바를 유지한다. 모바일 웹·모바일 앱을 추가하지 않는다.

**[ASSUMPTION]** 좁은 창에서도 한 열 카드와 `{spacing.sidebar-width}`의 사이드바를 유지한다. 긴 프로세스 표는 표 내부 스크롤/전체 명령 접근으로 처리하고 전체 창의 탐색을 가리지 않는다. 메인 시안의 880px 최소 폭·708px 높이를 잠정 기준으로 삼되 이는 Electron 최소 창 크기 검증값이 아니다. 실제 타이틀바·텍스트 확대·설정 창을 포함한 최소 크기는 구현 단계에서 검증한다. macOS 창 제어·메뉴 단축키를 따르되 웹 화면처럼 별도 헤더를 중복하지 않는다.

## Inspiration & Anti-patterns

- **확인됨 — Scratch:** 창 상단의 일체감, 절제된 컨트롤, 낮은 카드 장식 밀도가 영감이다. 구체 색·폭·재질은 Scratch에서 그대로 승인된 것으로 해석하지 않는다.
- **제외:** History 화면과 전역 history 차트, 별도 GPU 상세 라우트, 강제 단일 펼침, 프로세스 kill 조작, Tauri 전환.
- **[ASSUMPTION] 회피:** 숨겨지는 서버 탐색, hover로만 가능한 편집, 성공처럼 보이는 unknown·stale 값, 재진입마다 늘어나는 설정 창.

## Key Flows

주인공 **민수는 [ASSUMPTION]인 가상 인물**이며 개인·내부 GPU 모니터링 맥락도 임시 제안이다. 흐름은 확인된 사용 여정·진입점을 구체화한 초안이지 실제 조사 기록이 아니다.

### Flow 1 — GPUWatcher 실행 → 서버 선택 → GPU별 상태 및 프로세스 확인

1. 민수가 GPUWatcher를 실행한다. [ASSUMPTION] 마지막 서버가 유효하면 재선택하지만 왼쪽 서버 목록은 항상 보인다.
2. 민수가 사이드바에서 확인할 서버를 선택한다. 오른쪽에 해당 서버의 모든 GPU 요약이 나타난다.
3. VRAM 사용량/총량·사용률, UTIL·온도 숫자와 구간을 훑고 GPU 한 개의 헤더를 선택한다.
4. 해당 카드가 같은 자리에서 상세와 프로세스를 표시한다. 필요하면 기본 접힘인 `추가 지표`를 펼쳐 전력·클록·PCIe·MIG 등 기존 정보를 확인한다. 다른 카드도 펼친다; 첫 카드는 그대로 열려 있다.
5. **Climax:** 화면을 떠나지 않고 두 GPU의 상세·프로세스를 비교하며 어떤 값이 최신인지 또는 마지막 성공 값인지 구별한다.

**실패 분기:** 연결 실패 → 마지막 성공 데이터가 있으면 그 시각과 stale 경고를 유지한다. 없으면 수치를 만들지 않는다. [ASSUMPTION] 재시도 또는 사이드바 편집으로 연결 조건을 확인한다. 부분 프로세스 수집 실패 → 요약은 유지하고 해당 표만 알 수 없음. 실제 서버 접속 없이도 이 분기를 시안으로 확인한다.

### Flow 2 — 사이드바에서 서버 추가·편집

1. 민수가 사이드바 `+` 메뉴에서 서버 직접 추가를 선택한다. [ASSUMPTION] ServerEditor 시트가 열린다.
2. [ASSUMPTION] 연결 정보를 입력하고 저장한다. 로컬 설정 저장과 SSH 연결 확인은 구별한다.
3. 저장한 서버를 사이드바에서 선택해 GPU 요약을 확인한다.
4. 접속 정보를 수정해야 하면 해당 서버의 `…` 메뉴에서 편집을 선택한다. 같은 메뉴에서 삭제·모니터링 켜기/끄기·SSH 연결 테스트에도 접근한다. 여러 서버를 가져올 때는 `+` 메뉴의 SSH config 가져오기를 사용한다.
5. **Climax:** 서버 관리가 모니터링의 맥락을 떠나지 않고 이어지며 저장된 서버를 다시 선택할 수 있다.

**실패 분기 [ASSUMPTION]:** 입력 오류 → 필드 안내와 입력 보존; 저장 실패 → 원인과 재시도, 성공처럼 닫지 않음; 저장 후 SSH 인증 실패 → 설정은 보존하고 본문에서 연결 실패를 구분. 취소 → 기존 서버 정보 변경 없음. [서버 관리 시안](mockups/key-server-management.html)에 삭제 확인·모니터링 꺼짐·연결 테스트 결과·가져오기 미리보기와 실패 예시를 배치했다. 메뉴 위치는 확정됐으며 세부 시트·상태 표현은 수용된 잠정 기준이다.

### Flow 3 — 하나의 설정 창에서 외형 바꾸기

1. 민수가 GPUWatcher → 설정… 또는 ⌘,를 사용한다. 사이드바 설정 아이콘으로도 같은 창에 도달한다.
2. [ASSUMPTION] 이미 열린 설정 창이면 기존 창이 전면으로 이동한다.
3. 시스템 설정 따르기/라이트/다크 중 다크를 선택한다. [ASSUMPTION] 메인·설정 창이 함께 갱신되고 선택은 저장된다.
4. 시스템 설정 따르기를 선택하면 macOS 외형을 추종한다. 강제 라이트·다크 선택은 macOS 외형과 독립적이다.
5. **Climax:** 설정 창을 닫고 같은 서버·펼친 GPU 비교 맥락으로 돌아와 선택한 외형을 사용한다.

**실패 분기 [ASSUMPTION]:** 설정 저장 실패 → 오류를 표시하고 마지막 저장 모드로 복원, 재시도 제공. 시스템 변화 → 강제 모드는 바꾸지 않음. GPU 가용 알림 설정은 이 창이 아니라 해당 GPU의 펼친 카드에 둔다.

### Flow 4 — GPU가 사용 가능해지면 알림 받기

1. 민수가 서버를 선택하고 감시할 GPU 카드를 펼친다.
2. `사용 가능해지면 알림`을 켜고 저장된 조건을 읽는다. 이 흐름의 GPU 3은 기본 조건인 UTIL ≤5%·VRAM ≤1GiB·5분 지속을 사용하며 기존 사용자 지정 규칙은 덮어쓰지 않는다.
3. 다른 카드를 보거나 카드를 접어도 감시는 유지된다. 예시 GPU 3이 두 조건을 5분간 만족한다.
4. **Climax:** 해당 카드가 `사용 가능` 상태로 강조되고 macOS 알림이 서버명과 GPU 3을 알려준다.
5. 계속 유휴면 반복하지 않는다. 다시 사용됐다가 가용 조건을 재충족하고 이전 알림 후 15분이 지난 경우 재알림한다.

**실패 분기:** 데이터 수집 실패/unknown → 가용 확정·알림 없음, 마지막 성공 데이터는 stale로 보존. OS 권한 거부 → 카드 강조는 유지하되 배너를 보장하지 않음. [ASSUMPTION] 알림 설정 저장 실패는 입력 근처에서 안내하고 저장 성공으로 표시하지 않는다.

## 잠정 기준과 인계 경계

사용자의 비용·시간 효율 지시에 따라 아래 가역적 세부는 **[ASSUMPTION] 잠정 기준**으로 유지한 채 최종화했다. 전체 설계 승인을 각 수치의 개별 확정이나 실제 앱 검증으로 확대하지 않는다.

| 항목 | 잠정안·잔여 경계 |
|---|---|
| 프로세스 표 | PID·사용자·명령·VRAM. 기존 상세 표의 정보를 보존하고 명령 전체 값은 텍스트 선택·표 내부 스크롤로 접근. 실제 빈 목록·수집 불가를 구별. |
| 알림 세부 | on/off·저장 조건 읽기·사용자 지정값 보존·OS 설정 확인 안내. 새 임계값 편집기를 제외한 이번 범위는 수용됨; 향후 추가만 별도 범위 결정. |
| 서버 관리 | 기존 시트·확인·결과 시안 유지. 미저장 입력은 계속 편집/변경 버리기 확인. |
| 외형·복원 | 현재 토큰·밀도, 최초 시스템 테마, 마지막 유효 서버 재선택, 세션 동안 서버별 펼침 보존·재실행 시 접힘. |
| 플랫폼 | 최소 창 크기·VoiceOver·네이티브 포커스 및 알림 통합은 HTML만으로 검증 완료를 주장하지 않음. |
