- (decision) 사용자 요구: 현재 UI는 웹 느낌이 강하고 native desktop app 느낌이 부족하다. 더 native한 디자인을 원한다. 타이틀바와 메인 창이 자연스럽게 이어지지 않는 점이 주요 불만이다. 목표는 창 전체가 자연스럽게 연결되는 native desktop app 경험이다. 구체적인 색상, UI 패턴, 참고 앱, 구현 방식은 아직 선택되지 않았다.
- (decision) 사용자가 선호하는 시각 참고 앱으로 Scratch(https://github.com/erictli/scratch)를 지정했다. 사용자 표현: 자연스럽고 깔끔하면서 desktop native한 macOS app 디자인 느낌이 좋다. 참고 대상은 디자인이며 GPUWatcher의 Electron 런타임 변경을 요구한 것은 아니다.
- (event) Scratch README와 docs/screenshot.png를 조회하고 스크린샷을 시각 확인했다. 관찰: 왼쪽 상단 macOS 창 제어 버튼, 사이드바와 상단 영역의 연속된 밝은 표면, 절제된 아이콘 툴바, 얇은 구분선, 낮은 장식 밀도. 이 관찰의 개별 요소를 GPUWatcher에 적용할지는 아직 사용자 확인 전이며 기능 범위와 라이트/다크 정책도 미결정이다.
- (decision) 사용자가 디자인 핵심으로 창 상단의 일체감, 절제된 컨트롤, 카드 장식 최소화를 확인했다. Scratch를 참고한 native macOS desktop 느낌을 목표로 한다. 외형뿐 아니라 탐색 구조도 변경하는 설계 범위를 승인했다. 구체적인 탐색 구조와 사용자 여정은 아직 미결정이며 이번 확인은 제품 코드 구현 승인이 아니다.
- (decision) 사용자가 제시한 주요 사용 여정: GPUWatcher 실행 → 서버 선택 → GPU별 상태 및 프로세스 확인. 탐색의 진입 기준은 서버이며, 선택한 서버의 GPU 상태와 프로세스를 확인하는 것이 주요 목적이다. GPU 상태와 프로세스를 같은 화면에 동시 표시할지, 선택 GPU에 종속된 상세 영역으로 표시할지는 아직 미결정이다.
- (decision) 서버 선택 직후에는 해당 서버의 전체 GPU를 한눈에 보되 간략한 정보만 표시한다. 사용자가 명시한 지표는 VRAM 점유율, GPU UTIL, 온도 등이다. 앞서 요구한 프로세스 확인은 유지하되 첫 화면에 모든 프로세스를 펼쳐 표시하는 것으로 해석하지 않는다. 프로세스 확인으로 진입하는 방식과 상세 영역 위치는 아직 미결정이다.
- (decision) 사용자가 GPU 상세 진입 방식을 확정했다: 서버 선택 후 전체 GPU의 간략한 상태(VRAM 점유율, GPU UTIL, 온도 등)를 카드별로 보고, 해당 GPU 카드를 선택하면 그 카드가 제자리에서 펼쳐지며 해당 GPU의 상세 정보와 프로세스를 표시한다. 별도 상세 화면으로 이동하는 방식이 아니다. 이전의 카드 장식 최소화는 카드를 없애는 뜻이 아니라 절제된 카드 표현과 함께 적용한다. 동시 펼침 허용 여부와 서버 전환 시 펼침 상태 유지 정책은 아직 미결정이다.
- (decision) 사용자가 여러 GPU 카드의 동시 펼침을 허용하도록 확정했다. 각 GPU 카드는 독립적으로 펼치고 접을 수 있으며, 다른 GPU 카드를 펼쳐도 기존에 펼쳐진 카드를 자동으로 접지 않는다. 이를 통해 같은 서버의 여러 GPU 상세 정보와 프로세스를 함께 비교할 수 있다.
- (decision) 사용자가 탐색 레이아웃을 확정했다: 왼쪽 사이드바에 서버 목록을 항상 표시하고, 서버를 선택하면 오른쪽 본문에 해당 서버의 전체 GPU 요약 카드를 표시한다. GPU 카드는 제자리에서 독립적으로 펼쳐 상세 정보와 프로세스를 보여주며 여러 카드를 동시에 펼칠 수 있다. 타이틀바부터 사이드바와 본문까지 자연스럽게 이어지는 절제된 macOS desktop 디자인을 유지한다.
- (decision) 사용자가 테마 선택 옵션을 확정했다: 시스템 설정 따르기 / 라이트 / 다크의 세 가지를 사용자가 선택할 수 있어야 한다. 시스템 설정 모드에서는 macOS 외형 설정을 따르고, 라이트와 다크는 시스템 외형과 독립적으로 해당 모드를 사용한다. 최초 기본 선택값과 옵션 배치 위치는 아직 미결정이다.
- (decision) 사용자가 서버 추가와 편집의 진입 위치를 사이드바로 확정했다. 기존 History 화면은 새 UX에서 제거하기로 결정했다. 앱 설정 진입 위치는 사용자가 추천을 요청했으며 아직 미확정이다. History 화면 제거 결정은 이번 UX 설계 범위의 결정이며 백엔드 데이터 저장 정책이나 API 삭제를 별도로 승인한 것은 아니다.
- (decision) 사용자가 앱 설정 구성을 승인했다: macOS 메뉴바 GPUWatcher → 설정… 및 단축키 ⌘,를 기본 진입점으로 사용하고, 사이드바 맨 아래 작은 설정 아이콘도 제공한다. 모든 진입점은 같은 별도 설정 창을 연다. 시스템 설정 따르기 / 라이트 / 다크의 외형 선택은 그 설정 창에 둔다. 사이드바의 주요 역할은 서버 탐색과 서버 추가·편집이다.
- (decision) 사용자가 지금까지 합의한 UX 방향을 그대로 진행하도록 확인했다: Scratch 참고 native macOS 창 일체감, 절제된 컨트롤과 카드 장식, 서버 중심 사이드바 및 서버 추가·편집, GPU 요약 카드와 여러 카드의 독립적인 상세·프로세스 펼침, 별도 설정 창과 세 가지 테마 선택, History 화면 제거. 빠른 가정 기반 문서 초안과 시안 기반 공동 결정 중 작업 모드는 명시적으로 선택되지 않았다. 제품 코드 구현 승인은 아직 아니다.
- (decision) 사용자가 진행 순서를 확정했다: 1 빠른 설계 초안 작성 후 2 시안 중심 결정. 초안의 미결정 값은 [ASSUMPTION]으로 표시하고 최종 승인값으로 취급하지 않는다. 시안은 메인 창의 라이트/다크 및 별도 설정 창을 우선 대상으로 제안하며 전체 설계는 draft 상태로 유지한다.
- (assumption) 빠른 초안용 가정 묶음(사용자 승인 전): 중립적인 밝은/어두운 표면과 절제된 파란 포커스 색, 시스템 폰트, 서버 사이드바 220px, 카드 한 열 배치, 작은 간격 및 모서리; 초기 테마는 시스템 설정; 서버별 카드 펼침은 세션 동안 유지하고 재실행 시 초기화; 마지막 서버 재선택; 서버 추가·편집은 메인 창의 시트; 프로세스는 읽기 전용 PID/사용자/명령/VRAM 열; 사용 맥락은 개인·내부 GPU 모니터링; 사용자 여정 이름은 가상 인물 민수. - (decision) 사용자 시안 피드백: GPU UTIL, 온도, VRAM 점유율 및 VRAM 점유량을 숫자뿐 아니라 색깔 막대 등 시각적 요소로도 표현하여 한눈에 빠르게 파악하고 싶다. VRAM 점유량 표시를 요약 요구에 명시적으로 추가했다. 색상 구간 예시로 30퍼센트까지 초록, 60퍼센트까지 노랑, 그 이후 빨강을 제시했지만 예시라고 표현했으므로 최종 임계값은 미확정이다. 온도는 섭씨 절대값이므로 퍼센트 임계값을 그대로 적용하지 않는다. 막대 유형과 지표별 임계값을 확인한 뒤 시안과 시각·행동 계약에 반영한다.
- (decision) 사용자가 숫자와 얇은 색상 막대 병용 및 지표 구간을 승인했다. GPU UTIL과 VRAM 점유율: 0~30% 초록, 30% 초과~60% 노랑, 60% 초과 빨강. 온도: 60°C 이하 초록, 60°C 초과~80°C 노랑, 80°C 초과 빨강. VRAM 요약은 사용량 / 총량(GiB)과 백분율을 함께 표시한다. 색은 부하·온도 구간이며 빨강 자체가 오류·장애 또는 GPU별 안전 한계 판정은 아니다. unknown은 0이나 초록으로 표시하지 않고 stale은 마지막 성공 시각과 함께 구분한다.
- (assumption) 시안의 온도 막대 길이는 임시 0–100°C 척도로 표현하며 백분율·GPU 최대 허용 온도를 뜻하지 않는다. 실제 온도 숫자는 유지하고 길이만 0~100 범위로 제한하는 초안 규칙이다. 색상 hex와 막대 두께 4px는 아직 시각 검토 대상이다.
