# GPUWatcher Phase 2 UI 디자인 시스템 리팩터링 계획

## TL;DR

Phase 2는 GPUWatcher의 공통 UI 디자인 시스템을 절제된 dark developer-console 스타일로 정리하고, 기존 공통 컴포넌트에 적용하는 작업이다.

Phase 1의 macOS Native Frame과 Full-bleed Console shell은 완료된 기준선으로 취급한다. 되돌리거나 다시 설계하지 않는다.

이번 단계는 화면별 재설계가 아니다. Overview, Detail, History, Process Table, Settings의 레이아웃과 정보 구조는 유지한다. 화면 단위 feature component는 공통 토큰이나 primitive 변경 때문에 필요한 경우에만 제한적으로 수정한다.

실행 방식은 TDD 중심이다. 먼저 인벤토리를 만들고, 테스트를 고정한 뒤, 토큰/primitive/CSS를 변경하고, 필요한 호출부만 제한적으로 마이그레이션한다. 마지막에는 자동 검증과 Electron 시각 QA 증거를 남긴다.

- Source: `docs/draft/draft_0003.md`
- Target: `docs/plan/plan_0003.md`

## 결정 사항 / 내장 Design Contract

### Phase 2 디자인 계약

이 문서가 Phase 2의 binding design contract다. 별도 `DESIGN.md`는 명시적 승인이 있을 때만 만든다.

| 항목 | 결정 |
| --- | --- |
| 방향 | Supabase/Vercel의 절제된 문법에서 영감을 받은 GPUWatcher 고유 dark console UI |
| 정체성 | 브랜드 복제가 아니라 near-black 개발자 콘솔형 모니터링 도구 |
| 깊이감 | 낮은 대비의 1px border 중심, shadow는 최소화 |
| Radius | 작고 제한적인 radius, 과도한 pill 금지 |
| Motion | hover/focus에서 translate, scale, 위치 이동 금지 |
| Lime | primary action, 선택 강조, focus emphasis에만 사용 |
| Cyan | informational metric, chart에만 사용 |
| Green/Yellow/Red | success/warning/danger 상태 의미에만 사용 |
| Focus | 모든 interactive element에 명확한 `:focus-visible` |
| Density | `.app-shell[data-density]`와 component-level variable로 full/compact 유지 |
| 접근성 | accessible name, label, role, keyboard, live region, alert semantics 보존 |

### 금지 스타일

| 금지 | 이유 |
| --- | --- |
| Supabase/Vercel 브랜드 복제 | GPUWatcher 고유 문법이 필요 |
| white canvas / pastel SaaS | Phase 1 dark shell과 충돌 |
| marketing hero card / 과도한 pill | 화면 재설계 범위로 번짐 |
| neon terminal glow | 모니터링 데이터와 상태 색상을 방해 |
| glassmorphism | draft에서 명시적으로 금지 |
| 과도한 gradient | draft에서 명시적으로 금지 |
| glow shadow 중심 depth | 절제된 border-defined depth와 충돌 |
| bland dark admin | Phase 1 shell의 정체성 약화 |
| hover movement | 안정적인 monitoring UI와 충돌 |

### Button 결정

Phase 0 인벤토리에서 class-only button 사용이 모호하거나 반복 호출부가 많다고 확인되면 명시적 `Button` primitive를 선호한다. 반대로 React primitive가 불필요한 churn을 만들면 class-based `.btn` API를 의도적 계약으로 유지하고 테스트와 완료 보고서에 기록한다.

`Button`을 추가하는 경우 계약은 다음과 같다.

| 항목 | 계약 |
| --- | --- |
| 파일 | `src/components/ui/Button.tsx` |
| export | `src/components/ui.tsx`에서 re-export |
| variant | `primary`, `secondary`, `ghost`, `danger` |
| size | `sm`, `md` |
| 기본 type | `type="button"` |
| disabled | native disabled 지원 |
| className | base class를 유지하면서 확장 가능 |
| 접근성 | children 또는 `aria-label`을 통한 accessible name 유지 |
| motion | hover/focus에서 transform, translate, scale, layout shift 금지 |

### 호환성 계약

반드시 보존한다.

| 영역 | 보존 내용 |
| --- | --- |
| Phase 1 shell | Native Frame, full-bleed shell, `.app-shell[data-density]` |
| React Query | 기존 데이터 흐름과 query 동작 |
| Zustand | UI state, session-only density 동작 |
| Electron bridge | action-specific preload/IPC |
| Browser fallback | 명시적 `backend_unavailable` 오류 |
| Metric 표시 | `null`, `unknown`, `N/A`, missing value, chart gap을 0으로 변환 금지 |
| Server 기능 | CRUD, polling, refresh, process table 동작 |
| Diagnostics | `formatDiagnostic`, `sanitizeMessage`, 기존 diagnostic 문자열과 redaction |
| Export/import | 기존 export 보존 또는 제한적 caller migration |
| Token | 기존 CSS variable을 삭제하지 말고 alias로 호환 |
| 접근성 | label, role, accessible name, focus path, live region 유지 |

## Atomic Commit Strategy

명시적으로 요청받기 전에는 commit하지 않는다.

나중에 commit을 요청받으면 다음 순서로 atomic commit을 만든다.

| Commit | Scope |
| --- | --- |
| `test(ui): lock design-system primitive behavior` | button, form, toolbar, status, diagnostics, density 테스트 |
| `feat(ui): add semantic tokens and primitive contracts` | token, alias, Button 또는 class contract, surface classes |
| `refactor(ui): align shared form feedback table and drawer components` | shared component implementation과 CSS |
| `refactor(ui): migrate bounded shared UI callers` | 필요한 feature caller 호환 수정만 |
| `docs/ui: record phase 2 UI conventions` | `AGENTS.md` 또는 `src/AGENTS.md`가 실제로 바뀐 경우만 |

각 commit 전 관련 focused test를 통과시킨다. 마지막 전체 검증은 다음을 통과해야 한다.

```bash
npm run test -- --run
npm run build
npm run electron:build
```

Commit이 필요한 경우 attribution은 정확히 다음 literal text를 포함한다.

```text
Ultraworked with [Sisyphus](https://github.com/code-yeongyu/oh-my-openagent)

Co-authored-by: Sisyphus <clio-agent@sisyphuslabs.ai>
```

## 성공 기준

Phase 2 완료 조건:

- 공통 UI가 restrained GPUWatcher dark design-system grammar를 따른다.
- Semantic token이 추가되고 기존 variable은 alias로 유지된다.
- Button API 또는 class API가 명확하고 테스트된다.
- Form controls가 native semantics와 접근성을 보존한다.
- Toolbar가 compact, wrapping-friendly, density-aware하다.
- Status/feedback components가 일관되고 diagnostic/sanitize logic을 보존한다.
- Table/drawer primitive가 behavior regression 없이 정리된다.
- Feature screens는 필요한 범위에서만 제한 수정된다.
- Backend/Rust/DB/preload/IPC/helper/scheduler 변경이 없다.
- `npm run test -- --run` 통과.
- `npm run build` 통과.
- `npm run electron:build` 통과.
- Visual QA evidence가 Overview, Process Table, Settings, full density, compact density, minimum window를 포함한다.
- Completion report가 delivered/deferred/residual risk를 명확히 기록한다.
