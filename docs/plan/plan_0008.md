# GPUWatcher Phase 7: Product Polish & Release QA 실행 계획

Provenance: `/hyperplan` adversarial team 5인 라운드와 `plan` agent 산출물을 바탕으로 정리한 최종 실행 계획이다.

이 문서는 `docs/draft/draft_0008.md`를 실제 작업자가 바로 실행할 수 있는 Phase 7 계획으로 변환한다. 초안의 전체 QA 범위는 보존하되, 무한 체크리스트가 아니라 baseline, 결함 ledger, requirement-to-evidence map, 유한 risk matrix, rerun rule, 증거 산출물, 최종 review gate로 실행 가능하게 재구성한다.

## 목표

Phase 7의 목표는 현재 macOS Electron 앱을 제품 인계 가능한 수준으로 polish하고 release QA를 통과시키는 것이다. 새로운 제품 기능이나 대규모 화면 재설계를 하지 않는다.

검증 및 polish 대상은 다음이다.

- Overview, Server Detail, Live Monitor, Process Table, Settings의 화면 간 시각 일관성.
- Full / Compact density.
- default, minimum, wide, resize, maximize/restore 창 상태의 responsive와 overflow.
- keyboard-only flow, focus-visible, drawer/dialog focus, Escape, focus return.
- semantic structure, screen reader label, status state, accessible copy.
- reduced motion.
- loading, error, empty, success, stale, unknown, backend unavailable, mutation pending/success/error 상태 표현.
- macOS Electron native frame.
- plain Vite browser fallback.
- unit/integration/Rust/build/Electron smoke/packaged app/unsigned artifact validation.
- 현재 Electron/no-install SSH architecture를 정확히 설명하는 active docs.

## 범위

### 허용되는 변경

- `src/components/`, `src/features/`, `src/styles/`의 renderer UI polish.
- 반복되는 실제 결함이 확인된 경우의 작은 shared UI primitive 수정.
- screen-local test, smoke assertion, QA evidence 보강.
- 실제 검증 결과와 불일치할 때만 `docs/smoke-checklist.md`, README active setup, troubleshooting 문서 수정.
- QA 중 확인된 실제 회귀에 한해 최소 Rust/backend 수정. 이 경우 별도 ledger 항목, focused test, 재검증, scope justification이 필요하다.

### 금지되는 변경

- Tauri runtime, `@tauri-apps/*`, `src-tauri/`, `TAURI_` 설정, Tauri active setup.
- runtime path로서의 `gpuwatcher --json`.
- runtime API/UI/DB/settings/active docs의 `collectorCommand`, `collector_command`.
- user-configurable remote shell command, installed collector mode.
- 새로운 backend feature, DTO field, IPC action, database schema, query-key/store semantic, scheduler behavior, bulk backend action.
- generic renderer bridge: `invoke`, `runAction`, arbitrary helper dispatch, helper path exposure, renderer-callable `pollDueServers`.
- password SSH UI, private key textarea, interactive terminal prompt, remote process action.
- telemetry, analytics, cloud sync, auto update, auth.
- 새로운 chart framework, 새로운 component library, 전면적인 theme redesign, 또 다른 design system.
- unsigned `.app`, DMG, ZIP을 signed, notarized, uploaded, auto-updated, production release-ready, external distribution-ready라고 주장하는 문구.

### 제품 invariant

- Runtime flow는 React renderer -> action-specific Electron preload/IPC -> local Rust helper CLI -> `gpuwatcher-core` -> fixed no-install SSH commands -> local SQLite read model이다.
- Remote host 요구사항은 NVIDIA driver/`nvidia-smi`, POSIX shell, `ps`, macOS에서 가능한 key-based SSH뿐이다.
- Remote host에 GPUWatcher, nvitop, Python collector, collector package, agent, repository file, service install을 요구하지 않는다.
- Unknown/unavailable metric은 `null`/`unknown`으로 유지한다. `N/A`, `-`, optional section 누락, 사라진 PID를 0으로 바꾸지 않는다.
- Failed poll은 health/error metadata만 갱신하고 stale success를 보존하며 history sample을 추가하지 않는다.
- Electron은 `contextIsolation: true`, `nodeIntegration: false`를 유지한다.
- Plain Vite browser fallback은 static identity/read-only state와 명시적인 `backend_unavailable` error를 유지한다.

### T0. Baseline과 provenance

작업 시작 전 run id와 evidence directory를 만든다.

```bash
RUN_ID="phase-7-$(date -u +%Y%m%dT%H%M%SZ)"
```

```bash
git status --short | tee "$EVIDENCE_DIR/00-baseline/t0-git-status.txt"

git log --oneline -10 | tee "$EVIDENCE_DIR/00-baseline/t0-git-log.txt"

```

`$EVIDENCE_DIR/00-baseline/t0-provenance.md`에는 다음을 기록한다.

- run id, UTC 시작 시각.
- 현재 dirty worktree와 이미 존재하는 Phase 1-6 변경.
- `docs/draft/draft_0008.md`와 `docs/plan/plan_0008.md` 상태.
- 사용 가능한 smoke/test/package script.
- 작업 중 기존 변경을 되돌리지 않는다는 원칙.

이 baseline은 진단 자료이며 clean-tree blocker가 아니다. 관련 없는 기존 변경을 revert하지 않는다.

### Scoped diff rule

모든 edit는 defect ledger item 또는 requirement-evidence row와 연결되어야 한다.

각 변경 파일마다 다음 질문에 답할 수 있어야 한다.

- 어떤 requirement 또는 defect 때문에 수정했는가?
- 어떤 test 또는 manual QA artifact가 이를 증명하는가?
- 이 변경 때문에 어떤 downstream gate를 rerun해야 하는가?
- 이 파일은 Phase 7 범위 안인가?

답이 불명확하면 edit를 중단하고 scope를 나눈다.

## Risk-based QA matrix

초안의 전체 category는 보존하되, 실행은 finite minimum matrix와 escalation rule로 한다.

### 필수 최소 matrix

| Surface | 필수 sample |
| --- | --- |
| Overview | Full/default/success, Compact/default/success, minimum width/long server name, Plain Vite backend unavailable |
| Server Detail | Full/success, Compact/partial unknown, stale 또는 last-success, minimum width/long GPU UUID |
| Live Monitor | Full/stored history 또는 success, empty history, error/backend unavailable, minimum width/chart containment |
| Process Table | Full/success, Compact/success, keyboard-only row navigation, long command/user/PID identity, process detail drawer Escape/focus return |
| Settings | Full/default, Compact/default, validation error, SSH import long alias/warning, disabled reason, mutation pending/success/error |

| Runtime | 필수 sample |
| --- | --- |
| Plain Vite | Overview, Process Table, Settings static identity와 backend-unavailable |
| Electron dev | isolated data/HOME/SSH config smoke와 screenshots |
| Packaged `.app` | launch, first window, navigation, helper health 또는 clear helper error, native frame |
| Unsigned DMG/ZIP | artifact structure, non-empty, contained `.app`, helper outside ASAR, unsigned caveat |

| Input/accessibility | 필수 sample |
| --- | --- |
| Mouse | primary navigation과 주요 action |
| Keyboard only | sidebar, density, filters, tables, Settings forms |
| Escape | drawer/dialog close |
| Arrow navigation | Process Table |
| Long text | server name, hostname, username, GPU UUID, SSH key path, command, diagnostic, SSH config alias |
| Disabled control | visible reason 또는 주변 설명 |
| Reduced motion | `prefers-reduced-motion: reduce`에서 사용 가능 |

### Escalation rule

- Shared primitive defect: 해당 primitive를 쓰는 모든 screen test, accessibility check, screenshot, Electron dev smoke rerun.
- Screen-local defect: 해당 screen matrix row, affected tests, 관련 smoke step rerun.
- Smoke harness defect: smoke command rerun과 같은 user-visible path의 manual confirmation.
- Packaging defect: `npm run electron:pack`, packaged smoke, production DB before/after, unsigned caveat check rerun.
- Docs defect: docs grep gate와 active-doc accuracy review rerun.

## TDD 전략

자동화 가능한 결함은 TDD로 처리한다.

1. 결함을 ledger에 기록한다.
2. focused failing test를 먼저 추가하거나 갱신한다.
3. 가장 작은 test command로 red evidence를 저장한다.
4. 최소 fix를 구현한다.
5. focused test green evidence를 저장한다.
6. invalidated broader gate를 rerun한다.

대표 focused test command:

```bash
npm run test -- --run src/components/ui.test.tsx
npm run test -- --run src/features/overview/OverviewScreen.test.tsx
npm run test -- --run src/features/detail/ServerDetailScreen.test.tsx
npm run test -- --run src/features/history/HistoryMonitorScreen.test.tsx
npm run test -- --run src/features/processes/ProcessTableScreen.test.tsx
npm run test -- --run src/features/settings/SettingsScreen.test.tsx
npm run test -- --run src/features/settings/settingsModel.test.ts
npm run test -- --run src/lib/format.test.ts
```

Manual-only 결함은 macOS traffic light, titlebar drag, 시각 contrast처럼 합리적인 자동화가 어려운 경우에만 허용한다. 이 경우에도 before artifact, fix evidence, final manual verification artifact가 필요하다.

### Invalidation rule

- Shared primitive 변경은 dependent screen tests, accessibility checks, screenshots, Electron dev smoke를 invalidate한다.
- `src/styles/*` 변경은 visual/density/responsive screenshots와 최소 1개 Plain Vite check를 invalidate한다.
- Screen-local 변경은 해당 screen unit test, matrix row, screenshots, 관련 smoke step을 invalidate한다.
- `src/lib/api.ts`, preload, IPC, helper runner, scheduler, DTO, schema, query-key, store semantic 변경은 기본 금지다. 실제 회귀로 최소 수정이 필요하면 먼저 scope escalation을 기록한다.
- Smoke script 변경은 해당 smoke command와 evidence를 invalidate한다.
- Packaging config/helper resource 변경은 `npm run electron:pack`, packaged smoke, `npm run electron:dist:unsigned`, unsigned artifact validation을 invalidate한다.
- Docs 변경은 docs grep gates와 active-doc review를 invalidate한다.

## Wave 2. Audit and red tests

### T2.1 전체 시각 일관성 감사

대상:

- Overview
- Server Detail
- Live Monitor
- Process Table
- Settings

확인:

- page header, section header, button, input/select/checkbox, toolbar, summary strip, card/surface, table, status badge, diagnostic, loading/error/empty/result feedback, chart panel, drawer/dialog, danger zone, focus-visible, density.

완료 기준:

- 결함은 screenshot 또는 정확한 repro와 함께 ledger에 기록된다.
- 반복 결함은 shared primitive 후보로 분류한다.
- 1회성 결함은 screen-local로 유지한다.

### T2.2 Typography, formatter, unknown-state 감사

확인:

- UI 본문은 macOS system font stack 유지.
- display font는 제한적이고 의도적으로만 사용.
- 긴 server name/hostname/username/GPU UUID/command/path가 layout을 깨지 않음.
- 숫자 비교가 중요한 곳은 tabular treatment 검토.
- `null`은 `unknown`, 실제 숫자 0은 `0`.
- missing metric을 0으로 변환하지 않음.
- error와 command sanitization 유지.

완료 기준:

- formatter 불일치는 fix 전에 failing test를 추가한다.
- copy 변경은 의미 중심 assertion으로 test/smoke를 갱신한다.

### T2.3 Responsive, overflow, density 감사

Full/Compact에서 default/minimum/wide/resize/maximize-restore를 확인한다.

완료 기준:

- shell-level horizontal scrollbar 없음.
- table scroll은 table container 내부에 제한.
- drawer는 내부 scroll.
- chart는 parent width를 넘지 않음.
- Settings는 좁은 폭에서 stack.
- 중요한 정보가 compact에서 숨겨지지 않음.
- density별 JSX tree를 만들지 않음.

### T2.4 Keyboard, focus, semantics 감사

확인:

- sidebar navigation, density control, page actions, filters, tables, Process Table Arrow Up/Down, drawer/dialog, Settings forms, delete confirmation, SSH import candidate selection.

완료 기준:

- Tab 순서가 시각 순서와 일치.
- 숨겨진 element가 tab sequence에 남지 않음.
- 모든 interactive element에 focus-visible.
- Enter/Space semantics 정상.
- Escape close 정상.
- close 후 trigger 또는 원래 row로 focus return.
- selected/pressed/checked/current state가 accessibility tree에 노출.
- disabled control 이유가 주변 context로 이해 가능.
- titlebar drag region이 control을 가로채지 않음.

### T2.5 Screen reader와 semantic structure 감사

확인:

- navigation label, `aria-current="page"`, toolbar label, table caption/aria-label, sortable `aria-sort`, process row identity, visible status text, chart aria-label, loading `role="status"`, 필요한 error `role="alert"`, form label/input, helper/error `aria-describedby`, invalid `aria-invalid`, candidate disabled reason, decorative icon `aria-hidden`.

완료 기준:

- 색상/위치/border만으로 의미를 전달하지 않는다.
- 가능한 semantic fix는 focused test를 추가한다.

### T2.6 Reduced motion과 contrast 감사

확인:

- `prefers-reduced-motion: reduce`.
- drawer animation, hover transition, loading indicator, focus movement.
- tertiary/disabled/stale/warning/placeholder/table header/chart legend/command preview/helper text contrast.

완료 기준:

- button scale이나 position-translate hover를 추가하지 않는다.
- brand lime을 모든 상태 의미에 남용하지 않는다.

## Commit strategy

명시적으로 요청받지 않는 한 commit하지 않는다.

요청받으면 다음 단위로 작게 commit한다.

1. `test(phase7): add qa regression coverage`
2. `fix(ui): polish shared accessibility primitives`
3. `fix(overview): resolve phase 7 qa defects`
4. `fix(detail): resolve phase 7 qa defects`
5. `fix(history): resolve phase 7 qa defects`
6. `fix(processes): resolve phase 7 qa defects`
7. `fix(settings): resolve phase 7 qa defects`
8. `test(smoke): strengthen phase 7 smoke evidence`
9. `docs(qa): update phase 7 smoke and runtime notes`
10. `chore(release): validate unsigned package artifacts`

Commit 전에는 항상 다음을 확인한다.

```bash
git status --short
git diff --stat
git diff -- <paths>
git log --oneline -10
```

Commit attribution은 요청된 경우 정확히 다음을 포함한다.

```text
Ultraworked with [Sisyphus](https://github.com/code-yeongyu/oh-my-openagent)

Co-authored-by: Sisyphus <clio-agent@sisyphuslabs.ai>
```

## Draft 대비 변경 요약

### 추가

- **T0 baseline/provenance gate 추가**: dirty worktree에서도 기존 변경을 되돌리지 않고 안전하게 Phase 7 범위를 구분하기 위해 추가했다.
- **Run-specific evidence directory와 evidence manifest 추가**: release QA 주장이 stale artifact가 아니라 현재 run의 증거에 묶이도록 하기 위해 추가했다.
- **Production DB before/after check 추가**: packaged/manual 실행이 production DB를 오염시키지 않았음을 확인하기 위해 추가했다.
- **Live defect ledger 추가**: 발견된 문제를 ID, surface, runtime, repro, severity, 파일 후보, 필요한 evidence, disposition으로 추적하기 위해 추가했다.
- **Requirement-to-evidence map 추가**: 초안의 넓은 요구사항이 실제 command/manual procedure와 artifact로 연결되도록 추가했다.
- **Risk-based finite QA matrix 추가**: 초안의 모든 category를 보존하면서도 Cartesian product 폭발을 피하고 실행 가능한 최소 matrix와 escalation rule을 제공하기 위해 추가했다.
- **TDD와 invalidation rule 추가**: 자동화 가능한 결함은 red/green으로 잠그고, 변경 유형별 rerun 범위를 명확히 하기 위해 추가했다.
- **Manual macOS native-frame/accessibility gate 추가**: traffic lights, titlebar drag, focus, reduced motion, contrast 등 자동화가 어려운 macOS 품질을 finite gate로 검증하기 위해 추가했다.
- **Final review gates와 completion report 추가**: 완료를 자기보고가 아니라 plan compliance, scope fidelity, code quality, security/privacy, release language, test integrity 증거로 판정하기 위해 추가했다.
- **Atomic commit strategy 추가**: 나중에 commit 요청이 있을 때 bisect 가능한 단위와 repo attribution 규칙을 제공하기 위해 추가했다.

### 수정

- **초안의 넓은 감사 목록을 wave 기반 실행 계획으로 수정**: 각 wave에 수행 항목, acceptance criteria, command, evidence path를 붙여 downstream worker가 바로 실행할 수 있게 했다.
- **시각/접근성/runtime 항목을 requirement와 defect 중심으로 수정**: 단순 체크리스트가 아니라 관측된 결함과 증거로 수정 범위를 결정하게 했다.
- **Backend/Rust 범위를 수정**: 초안의 “실제 회귀 버그 수정” 허용을 유지하되, verified regression일 때만 최소 수정과 별도 justification을 요구하도록 제한했다.
- **Packaging 검증 표현을 수정**: packaged `.app`, DMG, ZIP은 local/internal unsigned QA artifact이며 production release-ready가 아님을 명시했다.
- **Docs update 기준을 수정**: 실제 실행한 검증과 active setup의 현재성에 근거할 때만 active docs를 수정하게 했다.
- **Smoke assertion 원칙을 수정**: exact layout class나 transient timestamp 대신 user-visible result와 sensitive-data guardrail 중심으로 바꿨다.
- **Clean worktree 조건을 수정**: clean 상태를 blocker가 아니라 provenance로 기록하게 했다.

### 삭제

- **Phase 7이 redesign이나 feature expansion으로 확장될 여지 삭제**: 목표를 product polish와 release QA로 제한했다.
- **모든 조합을 전부 수동 확인하는 비현실적 실행 방식 삭제**: category coverage는 유지하되 finite sample과 escalation으로 대체했다.
- **금지 runtime path의 active 가능성 삭제**: Tauri, runtime `gpuwatcher --json`, collector command, installed collector, generic IPC, password SSH, private key textarea, remote process action을 명시적으로 제외했다.
- **Unsigned artifact를 release-ready로 오해하게 할 표현 삭제**: signed/notarized/uploaded/auto-updated/production/external distribution claims를 금지했다.
- **모든 screenshot/log에 hash/mtime을 강제하는 과도한 evidence 요구 삭제**: package/release artifact와 final manifest에 필요한 freshness metadata만 요구하게 했다.
