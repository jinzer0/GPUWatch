# GPUWatcher Phase 4 Monitoring Workspace 리팩토링 계획

## TL;DR

Phase 4는 `Server Detail`과 `Live Monitor`를 Phase 1 shell, Phase 2 디자인 계약, Phase 3 Overview 패턴 위에서 하나의 restrained dark desktop monitoring workspace로 정리하는 프론트엔드 리팩토링이다.

핵심은 새 backend 기능이 아니라 현재 DTO, React Query, Zustand, chart primitive 계약을 그대로 보존하면서 Detail의 현재 상태 탐색과 History의 저장 시계열 탐색을 같은 시각 문법으로 맞추는 것이다. 구현자는 먼저 현재 동작을 characterization test로 고정한 뒤 Detail, History, CSS/visual QA 순서로 진행한다.

Backend, DTO, API, query key, Electron, preload, helper, scheduler, Rust, DB schema는 변경하지 않는다. `null`, `unknown`, missing metric, stale success, sample gap, fulfilled `{ ok: false }` refresh diagnostic은 사실 그대로 표시하고 0 또는 fabricated identity로 바꾸지 않는다.

- Source: `docs/draft/draft_0005.md`
- Target: `docs/plan/plan_0005.md`
- Binding prior work: `docs/plan/plan_0003.md`, `docs/plan/plan_0004.md`
- Provenance: hyperplan team rounds 1-3와 현재 코드 검사 결과를 반영한다.

## 현재 기준선

| 영역 | 현재 상태 |
| --- | --- |
| Phase 1 shell | macOS Native Frame과 full-bleed console shell은 완료된 기준선이다. 되돌리거나 재설계하지 않는다. |
| Phase 2 디자인 계약 | `docs/plan/plan_0003.md`가 binding design contract다. 별도 `DESIGN.md` 생성 없이 restrained dark developer-console 문법을 따른다. |
| Phase 3 Overview 패턴 | `docs/plan/plan_0004.md`의 plain header, compact summary strip, low-depth row, `.overview-*` scoped CSS, bounded diagnostics가 기준 패턴이다. |
| Detail controller | `useServerDetailController(selectedServerId)`가 detail query, stored history query, refresh mutation, live sample append를 소유한다. |
| Detail refetch | detail query refetch interval은 selected server polling interval 기반이며 최소 5초다. 현재 구현은 query data가 아직 없으면 10초 fallback 후 detail 수신 뒤 `max(pollingIntervalSeconds * 1000, 5000)`로 바뀐다. |
| Detail history query | `listGpuHistory(detailServerId, null, null, '1h')`와 `queryKeys.gpuHistory(detailServerId, null, null, '1h')`를 사용한다. |
| Detail history fallback | 저장 history가 준비되지 않았거나 GPU별 stored series가 비어 있으면 session live fallback을 사용한다. stored series 매칭은 현재 index 우선, UUID fallback이다. |
| Failed replacement snapshot | `health.status`에 `failed`가 포함된 detail은 live sample로 append하지 않는다. 실패 poll은 stale success를 보존하고 history sample을 추가하지 않는다. |
| Detail refresh | `refreshServer(id)` mutation이 fulfilled `{ ok: false }`를 반환해도 mutation success로 취급하고 bounded diagnostic을 표시한다. |
| Detail invalidation | refresh success 후 정확히 `queryKeys.detail(id)`, `queryKeys.gpuHistory(id, null, null, '1h')`, `queryKeys.overview`, `queryKeys.processes`를 invalidate한다. |
| History controller | `useHistoryMonitorController({ overview, selectedServerId })`가 local `activeServerId`, range, GPU, selected metrics, refresh feedback을 소유한다. |
| History server selection | incoming valid `selectedServerId`는 채택한다. local server select는 global Zustand `selectedServerId`를 쓰지 않고 local active server만 바꾸며 GPU 선택을 `all`로 reset한다. |
| History query | `listGpuHistory(activeServerId, null, null, range)`와 `queryKeys.gpuHistory(activeServerId, null, null, range)`를 사용한다. |
| History refresh | `Refresh history`는 React Query `historyQuery.refetch()`만 호출한다. `refresh_server` 또는 `refreshServer`를 호출하지 않는다. |
| History GPU filtering | GPU selector는 history series에서 만든 값으로 local filtering만 수행한다. backend query의 `gpuIndex`/`gpuUuid`는 계속 `null`이다. |
| History metrics | metric ID는 9개다: `gpuUtilizationPercent`, `memoryUtilizationPercent`, `memoryUsedMiB`, `temperatureCelsius`, `powerDrawWatt`, `encoderUtilizationPercent`, `decoderUtilizationPercent`, `pcieRxKibPerSec`, `pcieTxKibPerSec`. |
| History metric defaults | 기본 선택 metric은 `gpuUtilizationPercent`, `memoryUtilizationPercent`, `memoryUsedMiB` 3개다. 선택은 persistence가 없고 0개 선택을 허용하며 `No metrics selected`를 표시한다. |
| Chart math | `chartMath.ts`가 invalid timestamp drop, timestamp ascending sort, null/non-finite gap, polling gap threshold, single valid point rendering, range semantics를 담당한다. |
| Browser fallback | plain Vite는 Electron preload bridge가 없으므로 static identity와 read-only empty state 확인 용도다. Electron runtime QA를 대체하지 않는다. |

## 제품/설계 결정

### Monitoring Workspace 원칙

| 원칙 | 결정 |
| --- | --- |
| 시각 언어 | Phase 2의 restrained border-defined dark console을 따른다. glow, glass, hover movement, generic SaaS card stack을 금지한다. |
| 화면 관계 | Detail은 현재 상태와 GPU별 context, History는 저장된 시간 흐름 분석이다. 같은 문법을 쓰되 서로 다른 의미를 shared component로 억지 통합하지 않는다. |
| Header | 두 화면 모두 큰 floating card가 아닌 plain header를 쓴다. identity는 오류/empty/loading에서도 가능한 범위에서 유지한다. |
| Density | full/compact 모두 content를 유지하고 spacing/size만 줄인다. |
| Scope | scoped presentational classes를 우선한다. 공유 추출은 Detail과 History가 같은 의미와 behavior를 공유한다는 테스트/사용처가 있을 때만 한다. |
| Diagnostics | 전체 화면을 빨간 error card로 바꾸지 않는다. diagnostic은 bounded region에 두고 sanitization/redaction을 유지한다. |

### Detail 정보 구조

Detail 화면은 다음 순서로 정리한다.

```text
Plain page header
Compact server health strip
Bounded refresh/health/warning diagnostics
GPU compact panels
Per-GPU mini trend section
Per-GPU compact process list/table
```

| 구역 | 결정 |
| --- | --- |
| Plain header | `Server Detail`, server name, status, `username@host:port`, refresh button을 표시한다. Refresh accessible name에는 server name을 포함한다. |
| Loading/error/no selection | selected server가 없으면 기존 empty state를 유지한다. DTO/cache 없는 loading/error에서 server identity를 fabricated하지 않는다. |
| Health strip | Status, GPU count, busy/free, last success, poll interval, snapshot received, collector/driver/CUDA 중 현재 DTO에 있는 값만 compact하게 표시한다. 같은 정보를 header/GPU card에 반복하지 않는다. |
| Refresh diagnostic | fulfilled `{ ok: false }` refresh result는 rejected mutation이 아니다. Header 아래 bounded diagnostic으로 표시하고 기존 detail/context를 숨기지 않는다. |
| Health diagnostic | `lastErrorType` 또는 `lastErrorMessage`가 있을 때만 표시한다. `DiagnosticPanel`, `sanitizeMessage`, formatter guidance를 유지한다. |
| Warnings | optional collector warning은 bounded list로 표시한다. warning을 fatal error처럼 보이게 하지 않는다. |
| GPU panel | 거대한 nested dashboard card 대신 compact console panel/section을 사용한다. GPU index, name, UUID, MIG badge/current state, busy/free를 상단에 둔다. |
| Primary metrics | utilization, memory, temperature를 가장 먼저 읽히게 한다. |
| Secondary metrics | power, fan, PCIe, clocks, encoder/decoder/JPEG/OFA는 값이 있을 때 useful한 secondary/capability 정보로 둔다. |
| Diagnostic/capability metrics | unavailable/unsupported/collection warning은 primary metric과 같은 강조도를 쓰지 않는다. |
| Process list | process name/command, PID, user, GPU memory, 가능한 utilization을 compact row/table로 표시한다. no process는 “0 usage”가 아니라 no-process state다. |
| Mini trend | Detail 안의 history는 빠른 trend view다. utilization/memory 중심으로 하되 기존 `gpuHistoryMetrics` 계약을 무작정 삭제하지 않는다. 변경하려면 테스트로 보존/축소 이유를 고정한다. |

### Detail data contract freeze

| 계약 | 반드시 보존 |
| --- | --- |
| Detail query key | selected server가 있으면 `queryKeys.detail(selectedServerId)` |
| Detail empty key | selected server가 없을 때 현재 `['server-detail', 'none']` behavior 변경 금지 |
| Detail refetch | selected server polling interval 기반, 5초 floor |
| Detail history call | `listGpuHistory(id, null, null, '1h')` |
| Detail history key | `queryKeys.gpuHistory(id, null, null, '1h')` |
| Stored matching | stored series는 index 우선, UUID fallback |
| Session fallback | stored history loading 중 또는 GPU stored samples empty일 때 session live fallback |
| Failed replacement | `failed` replacement snapshot은 live append하지 않음 |
| Stale success | stale/failed 상태에서도 last successful snapshot metrics/processes를 숨기지 않음 |
| Refresh invalidation | detail, 1h history, overview, processes 정확히 invalidate |
| Refresh result | `{ ok: false }` fulfilled result는 diagnostic으로 표시하는 fulfilled mutation |

### Live Monitor 정보 구조

Live Monitor 화면은 다음 순서로 정리한다.

```text
Plain page header
Compact controls
Metric toggles
One-metric chart panels
State regions: loading/error/empty/no metrics
```

| 구역 | 결정 |
| --- | --- |
| Plain header | `Live Monitor`, `Stored GPU history`, current server/range/sample summary를 표시한다. DTO 없이 fabricated server name/status를 만들지 않는다. |
| Controls | Server, GPU, Range, Refresh history가 compact하게 한 줄 또는 wrap 가능한 toolbar에 남는다. Loading/error 중에도 현재 data가 허용하는 범위에서 controls를 숨기지 않는다. |
| Server select | local `activeServerId`만 변경한다. global Zustand `selectedServerId`를 쓰지 않는다. server 변경 시 GPU는 `all`로 reset한다. |
| Incoming selected server | prop으로 들어온 valid `selectedServerId`는 채택한다. invalid 또는 없음이면 current active server 또는 첫 overview row fallback을 유지한다. |
| GPU select | history series에서 option을 만들고 local filtering만 한다. backend query args는 `null, null` 유지다. |
| Range select | `parseHistoryRange` fallback과 query key/call semantics를 유지한다. |
| Metric toggles | 9개 metric ID를 유지한다. 기본 3개 선택, persistence 없음, 0개 선택 허용, `No metrics selected` 표시를 유지한다. |
| Refresh history | React Query `refetch()`만 수행한다. pending/success/error feedback은 controls 인근 bounded region에 둔다. |
| Chart panels | 선택 metric마다 하나의 panel을 만든다. 한 panel은 한 metric/unit만 가진다. 여러 GPU series는 같은 metric/unit 안에서만 허용한다. |
| Chart anatomy | title, unit, latest value, legend, time range/window, loading/empty/error state를 제공한다. |
| Grouping | chart grouping은 시각 조직화일 뿐이다. mixed-unit overlay나 dual-axis를 새로 만들지 않는다. |

| 계약 | 반드시 보존 |
| --- | --- |
| Query call | `listGpuHistory(activeServerId, null, null, range)` |
| Query key | `queryKeys.gpuHistory(activeServerId, null, null, range)` |
| Refresh | `historyQuery.refetch()`만 호출 |
| No backend refresh | `refreshServer`, `refresh_server`, new bridge action 호출 금지 |
| Local server select | global `selectedServerId`에 쓰지 않음 |
| Incoming selectedServerId | valid prop change는 local active server로 채택 |
| GPU reset | local server select 시 selected GPU를 `all`로 reset |
| GPU filtering | local `visibleSeries`만 변경 |
| Metric IDs | 9개 ID 유지 |
| Defaults | 기본 3개 metric 유지 |
| Zero selected | chart 대신 `No metrics selected` empty state |
| No persistence | selected metric/range/GPU persistence 추가 금지 |

### Chart integrity contract

`chartMath.ts`와 `TimeSeriesChart`의 observable behavior를 먼저 테스트로 고정한다.

| 항목 | 보존 기준 |
| --- | --- |
| Invalid timestamps | invalid timestamp sample은 drop한다. |
| Ordering | valid samples는 timestamp ascending으로 정렬한다. |
| Null/non-finite | null, undefined, NaN, infinite metric은 point가 아니라 gap이다. 0으로 연결하지 않는다. |
| Gap threshold | inferred time gap은 `deltaSeconds > max(pollingIntervalSeconds * 2, 120)`일 때만 gap이다. |
| Equality | `deltaSeconds === threshold`는 gap이 아니다. |
| Single sample | 단일 valid sample은 path가 없어도 point로 렌더링한다. |
| Percentage range | utilization 계열은 0-100 range를 유지한다. |
| Temperature/power | temperature/power에는 percentage range를 쓰지 않는다. |
| Mixed unit | 한 chart panel에 다른 unit metric을 섞지 않는다. |
| Optional metrics | unavailable optional metric은 unknown/gap으로 표현하고 primary metric처럼 과장하지 않는다. |

### Plain Vite fallback 결정

| 상태 | 결정 |
| --- | --- |
| Static identity | plain Vite에서도 가능한 static identity와 read-only empty state는 유지한다. |
| No distinct backend unavailable | 현재 screen/controller가 구분하지 못하는 별도 backend-unavailable state를 새로 발명하지 않는다. |
| No fake data | backend bridge 부재를 가리기 위해 fake server name/host/status/history sample을 만들지 않는다. |
| Electron QA | 실제 runtime behavior 확인은 Electron + isolated `GPUWATCHER_TEST_DATA_DIR`를 우선한다. plain Vite는 static/read-only fallback 확인에만 사용한다. |
