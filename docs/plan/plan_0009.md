# GPUWatch Phase 1: GPU 사용 가능 Watch + macOS 네이티브 알림

## Mission

GPUWatch의 새로운 **Watch 시스템**의 첫 번째 프로덕션 품질 수직 슬라이스를 구현한다.

사용자는 **Server Detail**에서 GPU를 선택하고 **“사용 가능 시 알림”*\*을 활성화할 수 있어야 하며, GPUWatch 창을 닫아도 이후 해당 GPU가 설정된 시간 동안 사용 가능 상태를 유지하면 **macOS 네이티브 알림**을 받아야 한다.

이 Phase는 다음 전체 경로를 반드시 구현해야 한다:

**Renderer UI → Electron IPC → Rust helper/core → SQLite 저장 → 성공적인 폴링 평가 → 알림 이벤트 생성 → Electron main → macOS Notification**

가짜 프론트엔드 전용 Watch 상태를 구현하지 말 것.

DB 스키마나 백엔드 일부만 구현하고 끝내지 말 것.

이 Phase 종료 시점에는 end-to-end로 동작이 반드시 검증 가능해야 한다.

# 1. 기존 아키텍처 불변 규칙

`React renderer`
→ `action-specific Electron preload/IPC`
→ `local Rust helper`
→ `gpuwatcher-core`
→ `system ssh`

이 구조를 반드시 유지한다.

특히:

* 원격 서버에 어떤 것도 설치 금지

* 임의 remote command 금지
* Tauri 금지
* `contextIsolation: true` 유지
* `nodeIntegration: false` 유지
* renderer에서 generic invoke / helper bridge 금지

* polling은 Electron main이 소유
* renderer는 polling 금지
* SQLite는 Rust/core가 소유 (Electron 직접 DB 쓰기 금지)
* `null`, `N/A`, missing metric을 0으로 해석 금지
* 실패한 poll은 성공 sample로 저장 금지

# 2. Phase 1 범위

단 하나의 Watch 타입만 구현:

## `gpu_available`

GPU가 “사용 가능” 상태가 되려면:

```text
gpuUtilizationPercent <= utilizationThresholdPercent
AND
memoryUsedMiB <= memoryThresholdMiB
```

기본값:

```text
utilizationThresholdPercent = 5
memoryThresholdMiB = 1024
sustainSeconds = 300
cooldownSeconds = 900
```

### 중요 규칙

* `null` utilization → 0으로 취급하지 말 것 (false)
* `null` memory → 0으로 취급하지 말 것 (false)
* metric 하나라도 unknown이면 false
* 한 번의 lucky sample로 알림 금지
* 조건이 sustainSeconds 동안 지속되어야 함
* 조건 만족 시 단 1회만 trigger
* 조건 깨지면 재-arm
* cooldown 동안 재-trigger 금지
* poll 실패 시 sustain 상태 초기화
* GPU snapshot에서 GPU 사라지면 sustain 초기화
* watch 생성 시 과거 상태로 즉시 trigger 금지
* enable/disable 시 상태 초기화

시간 기반(timestamp)으로 처리해야 함 (poll count 금지)

# 3. GPU 식별 규칙

우선순위:

1. GPU UUID (최우선)
2. GPU index (fallback)

저장 필드:

* `serverId`
* `gpuUuid` (가능하면)
* `gpuIndex`

규칙:

* UUID watch는 index 변경으로 다른 GPU로 이동 금지
* reboot/reconfig 후 index 재사용으로 잘못 매칭 금지

