# GPUWatcher Phase 6: Settings Console 리팩토링 구현 계획

이 문서는 `docs/draft/draft_0007.md`와 Phase 6 adversarial hyperplan bundle을 바탕으로 정리한 `docs/plan/plan_0007.md`의 최종 실행 계획이다. `docs/plan/`과 `docs/draft/`는 역사적 계획 기록이며, 이 문서는 현재 사용자 설치 문서가 아니다.

Phase 6은 frontend Settings console만 리팩토링한다. 이 계획은 작업자가 추가 인터뷰 없이 바로 실행할 수 있어야 한다.

## 1. 목표

Settings 화면을 SSH 기반 NVIDIA GPU 서버를 명확하고 안전하게 관리하는 절제된 server registry console로 리팩토링한다.

완성된 Settings 화면은 다음 작업을 지원해야 한다.

- 등록된 서버와 enabled 상태 확인.
- 새 서버 생성.
- 기존 서버 선택과 편집.
- 저장된 서버의 SSH 연결 테스트.
- 서버별 polling enable/disable.
- 명시적인 inline confirmation을 통한 저장된 서버 삭제.
- OpenSSH config 후보 scan.
- 단일 후보를 manual form에 적용.
- 유효 후보를 disabled 상태의 서버로 bulk 저장.
- import warning, duplicate, missing username, partial failure 이해.

Phase 1의 full-bleed app shell과 Phase 2의 restrained near-black, border-defined console grammar를 보존한다. Supabase/Vercel clone, floating dashboard, card-wall 회귀를 만들지 않는다.

## 2. 현재 기준 사실

작업 전 다음 사실을 기준으로 삼는다.

- `docs/plan/plan_0007.md`는 현재 존재하지만 비어 있다.
- Settings는 현재 fixed `25rem` side panel을 가진 two-column form/sidebar처럼 동작한다.
- SSH import UI는 현재 server form 안에 중첩되어 있다.
- Import candidate row는 큰 nested surface 형태다.
- Mutation error는 영역별 소유가 아니라 global funnel로 모인다.
- Enable mutation pending/error state는 row-scoped가 아니라 global에 가깝다.
- 기존 smoke/import selector는 visible `Import from SSH config` text와 region behavior에 의존한다.
- 현재 runtime은 Electron frontend -> action-specific preload/IPC -> local Rust helper -> core no-install SSH 구조다.
- 원격 host에는 NVIDIA driver/`nvidia-smi`, POSIX shell, `ps`, key-based SSH만 필요하다.
- Plain Vite browser fallback에서도 backend action이 unavailable일 때 Settings static identity와 manual form context가 보여야 한다.

- 명시 요청 없는 commit 또는 push.

## 5. Binding Visual Contract

하나의 connected registry workspace surface와 하나의 independent import workspace surface를 사용한다.

Nested surface는 다음에만 허용한다.

- Diagnostics.
- Delete danger confirmation.
- Empty state와 error state.

Pane, field group, candidate마다 별도 floating card를 만들지 않는다. Settings-specific CSS는 `.settings-*` selector로 소유한다. 여러 consumer와 test가 필요한 명확한 regression이 없는 한 broad shared primitive 변경은 범위 밖이다.

Density는 CSS variable로 제어한다. Compact density는 spacing만 줄일 수 있다. Field, metadata, warning, candidate reason, action, feedback을 제거하면 안 된다.

Sticky editor footer는 기본적으로 거부한다.

## 6. Target Information Architecture

Settings page는 다음 구조를 사용한다.

```text
Page header
Registry summary strip
Server registry master-detail workspace
├── Server list
└── Server editor
SSH config import workspace
```

SSH import workspace는 editor `<form>` 밖의 sibling이어야 한다. CSS-only 이동이 아니라 실제 markup 구조로 분리한다.

## 7. Page Header 결정

`Settings / Server registry` identity를 유지한다.

Header action:

- `New server`는 editing state를 clear하고 editor를 new-server mode로 연다.
- `Import SSH config`는 import workspace heading으로 scroll하고 programmatic focus만 수행한다.
- `Import SSH config`는 scan, mutation, URL state 추가, selection 변경을 하지 않는다.
- Scan action은 import workspace 내부에 유지하며, 같은 patch에서 test/smoke selector를 갱신하지 않는 한 기존 accessible name을 유지한다.

Validation error나 mutation error를 page header에 배치하지 않는다.

## 8. Registry Summary

Server query data가 존재할 때만 pure helper로 summary를 만든다. Loading 또는 error 상태에서 거짓 `0 servers` summary를 표시하지 않는다.

Summary에 표시할 수 있는 정보:

- Total servers.
- Enabled servers.
- Disabled servers.
- Optional current editing label.

Summary는 compact하고 presentation-only여야 한다. 화면의 주인공이 되면 안 된다.

Acceptance:

- Loading state가 `0 servers`라고 말하지 않는다.
- Error state가 `0 servers`라고 말하지 않는다.
- Empty success state는 no servers를 표시할 수 있고 new server form은 계속 사용 가능하다.

## 9. Server Registry Workspace

Desktop/default layout:

```text
server list | editor
```

Requirements:

- Left pane width: `17rem` to `20rem`.
- Right pane: `minmax(0, 1fr)`.
- `min-width: 0`, wrapping/truncation, local overflow control을 사용한다.
- Default desktop은 `1280x860`에서 검증한다.
- Settings-specific breakpoint는 Electron `1024x720`에서 검증한다.
- Settings breakpoint에서는 list가 editor 위로 stack될 수 있다.
- Shell content는 scroll 가능해야 하지만 app shell 자체가 horizontal overflow를 만들면 안 된다.

## 10. Server Row

Row 안에 nested interactive control을 두지 않는다.

구조:

- Identity와 metadata를 담는 primary row-selection button 하나.
- Sibling compact enable/disable button 또는 accessible switch 하나.

Selected state는 다음을 포함한다.

- `aria-current="true"`.
- 색상만이 아닌 visible text, rail, status 또는 동등한 indicator.

Row content:

- Server name.
- `username@host:port`.
- Enabled/disabled state.
- Polling interval 같은 유용한 metadata.
- 필요한 경우 current editing state.

Enable/disable behavior:

- 기존 enable/disable mutation을 사용한다.
- Pending과 error state는 row-scoped다.
- Unrelated row를 global disable하지 않는다.
- Disable이 remote server shutdown처럼 보이면 안 된다.
- Optimistic update를 새로 도입하지 않는다.

## 11. Server Editor 구조

Editor form은 semantic section, fieldset, separator를 사용한다. Field마다 card를 만들지 않는다.

필수 section:

```text
Identity
SSH connection
Polling
Remote requirements
Connection test
Actions
Danger zone
```

### Identity

- `Name`을 유지한다.
- Editing 상태에서 유용하다면 saved server identity metadata를 표시한다.
- Server ID를 editable input으로 노출하지 않는다.

### SSH Connection

Fields:

- Host.
- SSH port.
- Username.
- SSH key path.

Requirements:

- Native input을 유지한다.
- Label과 input을 연결한다.
- SSH key path helper copy는 이것이 local private key file path이며 key material이 아님을 명확히 한다.
- SSH key path는 one-line이어야 한다.
- Private key material paste는 reject한다.
- Sensitive path를 unrelated UI 영역에 복제하지 않는다.

### Polling

Fields:

- Polling interval seconds.
- Enabled.

Requirements:

- Empty polling interval은 `null` 의미를 보존한다.
- `0`은 invalid다.
- Range는 `1` to `86400`을 유지한다.
- Enabled는 native checkbox semantics 또는 동등한 accessible switch semantics를 사용한다.
- Label click으로 control이 toggle되어야 한다.

### Remote Requirements

Compact callout 또는 disclosure copy를 사용한다. No-install product contract를 보존한다.

- No remote GPUWatcher install.
- No remote nvitop install.
- No remote Python collector.
- No collector package.
- Requires NVIDIA driver and `nvidia-smi`.
- Requires POSIX shell.
- Requires `ps`.
- Requires key-based SSH from macOS.

Active runtime path로 `gpuwatcher --json`를 언급하지 않는다.

## 12. Validation 결정

Form에는 controlled custom validation과 `noValidate`를 사용한다.

Required validation rules:

- Name은 trim 후 required다.
- Host는 trim 후 required다.
- Username은 trim 후 required다.
- SSH port는 `1` to `65535` integer여야 한다.
- Polling interval은 empty 또는 `1` to `86400` integer여야 한다.
- SSH key path는 one-line filesystem path여야 한다.
- Private key material은 reject한다.

Accessibility requirements:

- Field error map을 유지한다.
- Stable helper/error ID를 사용한다.
- Invalid field에는 `aria-invalid`를 적용한다.
- Input은 helper와 error text를 `aria-describedby`로 연결한다.
- Native validation bubble과 custom validation message가 충돌하지 않게 한다.
- Test가 더 명확한 equivalent wording을 고정하지 않는 한 기존 wording/range를 보존한다.

## 13. Action Hierarchy

Primary action:

- `Save server`

Secondary actions:

- `Test SSH connection`
- `Cancel` 또는 `New server`

Danger action:

- `Delete server`, edit mode에서만 danger zone 내부에 표시.

Rules:

- `Save server`는 primary다.
- `Test SSH connection`은 secondary이며 saved server ID가 있을 때만 enabled다.
- New unsaved form은 disabled test reason을 보여준다.
- Cancel/New은 secondary 또는 ghost다.
- Delete는 normal form action row에 두지 않는다.
- 모든 button은 명시적인 `type`을 가져야 한다.
- Enter submit behavior는 form save로 유지한다.
- Save 중에는 editor input/action과 같은 서버의 conflicting save/delete/toggle control만 disable한다.
- Unrelated server row, import workspace, unrelated manual work를 disable하지 않는다.

## 14. Connection Test State Ownership

Connection test result와 error는 tested saved server ID와 연결한다.

Test result는 다음 조건에서만 render한다.

- Result가 현재 saved editor/server ID에 속한다.
- Editor가 여전히 해당 saved server의 edit state다.

Required race guard:

- `test(A)`를 시작한다.
- 다른 server, new form, 또는 delete flow로 전환한다.
- `test(A)`가 resolve된다.
- 현재 editor에 A result가 나타나지 않음을 assert한다.

Import candidate의 `Use in form`은 stale connection test result를 clear 또는 hide해야 한다. 금지된 selection/editing side-effect 변경을 도입하면 안 된다.

## 15. Delete Confirmation 결정

Phase 6은 inline two-step confirmation을 기본으로 사용한다.

사용 금지:

- Shared dialog primitive.
- `window.confirm`.

Confirmation UI는 다음을 보여야 한다.

- Server name.
- Local saved configuration만 삭제된다는 설명.
- Remote file, process, server state는 변경하지 않는다는 설명.
- Cancel.
- Confirm delete.

Focus behavior:

- 첫 Delete click 후 focus가 inline confirmation 내부로 이동한다.
- Cancel은 focus를 Delete로 되돌린다.
- Successful delete 후 focus는 New server 또는 editor heading으로 이동한다.
- Failed delete는 danger zone에 머물며 sanitized scoped error를 표시한다.

State behavior:

- Delete target을 capture한다.
- Editor change와 successful delete에서 confirmation state를 cleanup한다.
- Explicit confirmation 전에는 delete API를 호출하지 않는다.
- Pending 중 duplicate submit을 막는다.

## 16. Error Architecture

Global mutation-error funnel을 대체한다. Local error를 추가하면서 global duplicate를 남기지 않는다.

각 error는 owner 영역에 정확히 한 번만 나타난다.

- Server list load error: registry workspace.
- Validation/save error: editor.
- Connection test error: connection test panel.
- Delete error: danger zone.
- Enable/disable error: row 또는 compact registry feedback.
- SSH import scan error: import workspace.
- Bulk save errors: bulk result.

모든 error는 기존 sanitization/redaction behavior를 사용한다. Raw private key material, sensitive local path, token, unredacted backend diagnostic을 노출하지 않는다.

## 17. SSH Config Import Workspace

Import workspace는 editor form과 독립적이다.

구성:

- Heading과 explanatory copy.
- Scan action.
- Pending/error/backend unavailable state.
- Global warnings.
- Candidate list/table/ledger.
- Bulk selection controls.
- Bulk result.

Manual server form은 다음 상황에서도 계속 사용 가능해야 한다.

- Import scan failure.
- Backend unavailable.
- Empty candidate list.
- Partial bulk save failure.

## 18. Candidate Presentation

Compact table/list/ledger를 사용하고 card wall row를 만들지 않는다.

각 candidate에 표시한다.

- Valid selectable candidate용 checkbox.
- Alias.
- `user@host:port`.
- Readiness.
- Skip reason.
- Warnings.
- `Use in form`.

Requirements:

- Disabled candidate는 selectable하지 않다.
- Disabled reason은 `aria-describedby`로 노출한다.
- Safe stable DOM ID를 생성한다. Raw SSH alias를 DOM ID로 쓰지 않는다.
- Candidate ordering을 보존한다.
- Duplicate semantics를 보존한다.
- Missing username handling을 보존한다.
- Unsupported `ProxyJump` / `ProxyCommand` warnings를 보존한다.
- Browser fallback behavior를 보존한다.
- Preview metadata를 save payload에 포함하지 않는다.
- `Use in form`은 candidate draft를 manual form에 복사하지만 저장하지 않는다.
- 긴 alias, host, warning은 shell overflow 없이 wrap/truncate한다.

## 19. Bulk Import

기존 sequential saves를 보존한다. Bulk backend action을 추가하지 않는다.

Rules:

- Valid selected candidate만 저장한다.
- Invalid candidate는 skipped 처리한다.
- 각 save failure는 독립적으로 수집한다.
- Partial success는 계속 표시한다.
- Bulk result는 saved/skipped/failed breakdown을 포함한다.
- Bulk imported server는 disabled다.
- Import 전후 automatic connection test를 실행하지 않는다.
- Bulk result는 live/status semantics를 사용한다.
- Bulk result가 candidate list를 밀어내면 안 된다.

## 20. State Ownership과 Refresh Race

Controller refactor는 UI state ownership에 한정한다.

Allowed controller work:

- Area-specific mutation errors.
- Selected/editing state helpers.
- Registry summary.
- Delete confirmation UI state.
- Row-scoped pending/error server IDs.
- Candidate/import presentation helpers.
- Form validation metadata.
- Tested saved server ID 기반 connection test ownership.

Required state protections:

- Query refresh가 dirty editor state를 지우면 안 된다.
- Save success는 기존 behavior에 맞게 selected/editing state를 update할 수 있다.
- Delete target은 confirmation 전에 capture한다.
- Delete confirmation은 editor change와 success에서 clear한다.
- Candidate `Use in form`은 자동 저장하지 않는다.
- API call order 변경 금지.
- Payload semantic 변경 금지.
- Store semantic 변경 금지.
- Bulk save semantic 변경 금지.

## 23. Implementation Tasks

### T0. Baseline Characterization

Owner: frontend TDD worker.

Recommended delegation: `visual-engineering` with `frontend` and `programming`.

Steps:

1. Scope에 적힌 current Settings files와 tests를 읽는다.
2. Markup/CSS 변경 전에 tests를 추가 또는 갱신한다.
3. Refactor 후에도 유지해야 할 current behavior를 잠근다.
4. CSS class assertion보다 user-facing queries를 우선한다.

Acceptance criteria:

- Tests cover page/registry identity.
- Tests cover loading, error, no servers, one server, many servers.
- Tests cover current form population, trim behavior, `null` mapping, enabled value, payload whitelist.
- Tests prove forbidden payload fields such as collector command data are not sent.
- Tests cover current import scan and candidate behavior before moving markup.
- Focused test command가 준비되어 있다.

```bash
npm run test -- --run src/features/settings/settingsModel.test.ts src/features/settings/SettingsScreen.test.tsx
```

### T1. Model Helpers and Validation

Owner: frontend model worker.

Recommended delegation: `quick` 또는 `unspecified-low` with `programming`.

Implement in `settingsModel.ts` and `settingsModel.test.ts`.

Required helpers 또는 equivalent deterministic logic:

- Known server data만 받는 registry summary helper.
- Controlled validation result와 field error map.
- Stable helper/error ID strategy.
- Raw alias를 직접 쓰지 않는 safe stable candidate DOM ID helper.
- Component complexity를 줄일 수 있다면 candidate presentation metadata helper.
- Trim과 `null` mapping을 보존하는 payload preparation helper.

Acceptance criteria:

- Name/host/username required checks pass.
- Port `1-65535` validation passes.
- Polling empty 또는 `1-86400` validation passes.
- Private key material rejection passes.
- One-line key path validation passes.
- Empty key path maps to `null`.
- Empty polling interval maps to `null`.
- Preview metadata is excluded from save payload.
- Candidate IDs are safe and stable.
- Disabled candidate reasons are available for `aria-describedby`.

### T2. Controller State Ownership

Owner: frontend controller worker.

Recommended delegation: `unspecified-high` with `programming`.

Implement in `useSettingsController.ts` and integration tests.

Required work:

- Global mutation error funnel을 area-specific error state로 대체한다.
- Row-scoped enable/disable pending/error를 추적한다.
- Save pending을 추적하고 same-editor/same-server conflicting controls만 disable한다.
- Connection test result/error를 tested saved server ID로 추적한다.
- Delete confirmation state와 captured delete target을 추적한다.
- Query refresh가 dirty editor state를 지우지 않게 한다.
- Candidate `Use in form`이 stale connection test state를 clear 또는 hide하게 한다.
- Existing action calls와 data refresh behavior를 보존한다.

Acceptance criteria:

- Late connection test response for stale server is not rendered.
- Enable/disable pending/error affects only the relevant row or registry feedback.
- Save pending disables editor inputs/actions but not unrelated rows/import workspace.
- Delete target remains stable through confirmation.
- Delete confirmation clears on editor change and successful delete.
- Area errors render exactly once.
- Existing Settings data refresh behavior still occurs after successful mutations.
- No API action order or payload semantics change.

### T3. Registry Workspace Implementation

Owner: frontend UI worker.

Recommended delegation: `visual-engineering` with `frontend` and `programming`.

Implement in:

- `SettingsScreen.tsx`
- `ConfiguredServersPanel.tsx`

## 27. Atomic Commit Strategy

명시 요청이 없으면 commit 또는 push하지 않는다.

나중에 commit을 요청받으면 다음 atomic boundary를 사용한다.

1. `test(settings): characterize phase 6 settings behavior`
   - Implementation 전 focused model/screen tests를 추가 또는 갱신한다.
2. `refactor(settings): scope model validation and controller state`
   - Helpers, scoped errors, pending ownership, test ownership, delete confirmation state를 추가한다.
3. `feat(settings): rebuild registry and editor workspace`
   - Header, summary, master-detail registry, editor sections, validation ARIA, actions, delete confirmation을 구현한다.
4. `feat(settings): separate ssh import workspace`
   - Import를 form 밖으로 이동하고 compact candidates, safe IDs, bulk result behavior를 구현한다.
5. `style(settings): apply responsive console density`
   - Settings-scoped layout, density variables, overflow handling, responsive behavior를 추가한다.
6. `test(settings): complete phase 6 verification`
   - 필요한 final test adjustment와 QA 기록을 정리한다.

각 commit은 해당 범위의 tests가 통과하는 상태여야 한다. Backend, docs cleanup, unrelated screen edit를 섞지 않는다.

Commit 요청이 있을 경우 모든 commit attribution은 정확히 다음을 포함해야 한다.

```text
Ultraworked with [Sisyphus](https://github.com/code-yeongyu/oh-my-openagent)

Co-authored-by: Sisyphus <clio-agent@sisyphuslabs.ai>
```

## 28. Rollback Notes

Phase 6은 frontend Settings-only refactor이므로 rollback은 이 phase에서 변경한 Settings files와 `src/styles/screens.css`로 제한되어야 한다.

Rollback safety checks:

- Rollback 후 focused Settings tests를 다시 실행한다.
- Shared CSS가 변경되었다면 full frontend tests를 다시 실행한다.
- Manual form이 이전 payload contract로 저장되는지 확인한다.
- Rollback 전 forbidden backend, IPC, DTO, helper, Rust, SQLite, scheduler, query-key, store 변경이 도입되지 않았는지 확인한다.

Riskiest rollback areas:

- Controller state ownership.
- Import workspace relocation outside the form.
- Delete confirmation state and focus behavior.
- Settings-scoped responsive CSS.
