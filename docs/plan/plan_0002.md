# GPUWatcher macOS Electron Full-Bleed Console 리팩토링 계획서

## 1. 문서 목적과 계획 원칙

이 문서는 `docs/draft/draft_0002.md`를 실제 구현 가능한 최종 실행 계획으로 정리한 문서이다.

이번 작업의 목표는 GPUWatcher UI를 현재의 floating web-dashboard 카드형 구조에서 macOS Electron 데스크톱 앱다운 **Native Frame + Full-bleed Console** 구조로 리팩토링하는 것이다. 핵심은 기능 추가가 아니라 Electron 창 chrome, React Shell, CSS 토큰/레이아웃, 그리고 필요한 최소 화면 header 정리를 통해 앱 전체가 하나의 native operations console처럼 보이고 동작하게 만드는 것이다.

계획 원칙은 다음과 같다.

- 현재 런타임은 Electron-only이다. Tauri는 historical context이며 재도입하지 않는다.
- 작업 범위는 시각적·구조적 UI 리팩토링으로 제한한다.
- preload, IPC, helper contract, scheduler, Rust core, DB schema, 저장 데이터 동작은 변경하지 않는다.
- `.app-shell[data-density]` root는 유지해 리스크를 줄이고, 내부에 semantic shell 구조를 추가한다.
- TDD 방식으로 Shell 동작 테스트를 먼저 고정하거나 구현과 같은 작은 루프로 작성한다.
- 화면 전체 재디자인이 아니라 shell과 충돌하는 최상단 header만 필요한 만큼 정리한다.
- macOS Electron 수동 visual QA는 필수 gate이다. 실행할 수 없으면 완료가 아니라 blocker 또는 residual risk로 보고한다.
- 명시적으로 요청받지 않는 한 commit/push를 하지 않는다.

## 2. Locked Decisions

| 항목 | 결정 |
|---|---|
| Runtime | Electron-only macOS desktop app |
| 금지 런타임 | Tauri 재도입 금지 |
| 작업 성격 | visual/structural UI refactor only |
| 핵심 방향 | Native Frame + Full-bleed Console |
| 디자인 기준 | calm dark native operations console |
| Electron frame | macOS에서 `titleBarStyle: 'hiddenInset'` 사용 |
| Window controls | macOS native traffic lights 유지, custom close/minimize/maximize 버튼 금지 |
| BrowserWindow 표시 | `show: false`, `ready-to-show` 이후 `show()` |
| BrowserWindow 배경 | window token과 맞는 dark `backgroundColor` |
| Window size | 기존 `width: 1280`, `height: 860`, `minWidth: 1024`, `minHeight: 720` 유지 |
| Web security | `contextIsolation: true`, `nodeIntegration: false` 유지 |
| Preload | 기존 `preload-runtime.cjs`와 action-specific bridge 유지 |
| Scheduler | Electron main ownership 유지 |
| Shell root | `.app-shell[data-density]` 유지 |
| Shell semantic children | `.window-titlebar`, `.app-sidebar`, `.app-content`, `.page-container` 추가 |
| Scroll owner | content pane만 scroll, shell/titlebar/sidebar/body는 second page scroll 생성 금지 |
| Density state | Zustand `densityMode`, default `full`, session-only 유지 |
| Navigation tabs | Overview, Server Detail, Live Monitor, Process Table, Settings 유지 |
| Counts | `overview === null`이면 `unknown`, `overview === []`이면 `0 servers`와 `0 online` |
| Metrics | unknown/null/unavailable metric은 `0`으로 변환하지 않음 |
| Browser fallback | static identity/read-only empty state와 명시적 `backend_unavailable` 유지 |
| Design system | 이번 shell refactor에는 별도 `DESIGN.md` 필수 아님. 이 문서의 Design Contract를 기준으로 구현한다. 별도 `DESIGN.md`는 future reusable primitives가 확장될 때 optional follow-up이다. |

## 3. 명시적 Non-goals

이번 작업에서 구현하지 않는 항목은 다음과 같다.

- backend feature 추가
- Rust core 변경
- SQLite schema 또는 migration 변경
- preload bridge API 변경
- generic `invoke` 추가
- generic `runAction` 추가
- renderer-callable `pollDueServers` 추가
- helper path renderer 노출
- helper contract 변경
- scheduler lifecycle 변경
- server CRUD 동작 변경
- polling 동작 변경
- remote command 설정 기능 추가
- Tauri 관련 코드, 패키지, 문서, 설정 재도입
- custom traffic-light/window-control 버튼 구현
- 전체 화면별 상세 UI 재디자인
- fake demo row로 Electron/backend 오류 숨기기
- unknown/null metric을 `0`으로 치환
- signing, notarization, auto-update, external release pipeline 작업
- 명시적 요청 없는 commit/push

## 4. Current-State Facts

현재 저장소 기준 구현 사실은 다음과 같다.

- Electron main은 `BrowserWindow`를 `width: 1280`, `height: 860`, `minWidth: 1024`, `minHeight: 720`으로 생성한다.
- 현재 `electron/main.ts`에는 `show: false`, `titleBarStyle: 'hiddenInset'`, app background color, `ready-to-show` show flow가 없다.
- 현재 `webPreferences`는 `preload-runtime.cjs`, `nodeIntegration: false`, `contextIsolation: true`를 사용한다.
- scheduler는 Electron main에서 시작되고 `before-quit`에서 stop된다.
- 현재 `Shell.tsx` root는 `<div className="app-shell" data-density={densityMode}>`이다.
- 현재 shell layout은 `.app-shell-layout mx-auto grid max-w-7xl grid-cols-[17rem_1fr] gap-6` 형태의 centered dashboard 구조이다.
- 현재 sidebar는 sticky `.panel`이고 hero copy `Remote GPU console`, 설명 문구, server/online metric cards, nav buttons, density control을 포함한다.
- 현재 main은 `<main className="min-w-0">`이며 content pane 단독 scroll 구조가 아니다.
- 현재 tabs는 Overview, Server Detail, Live Monitor, Process Table, Settings이다.
- 현재 Zustand store는 `activeTab`, `activeScreen`, `densityMode`를 관리하고 `densityMode` 기본값은 `full`이다.
- browser fallback은 Electron preload bridge가 없을 때 static identity/read-only empty state와 명시적 backend unavailable error를 유지해야 한다.
- DTO와 metric 표시 규칙상 unknown/unavailable 값은 `unknown` 또는 `null`이어야 하며 `0`으로 바꾸면 안 된다.

## 5. Design Contract

### 5.1 Overall Surface

구현할 UI는 web dashboard가 아니라 macOS native desktop operations console처럼 보여야 한다.

필수 기준:

- 앱은 BrowserWindow 전체를 채운다.
- titlebar, sidebar, content가 하나의 window surface로 연결된다.
- shell/titlebar/sidebar에는 radius, shadow, glow를 적용하지 않는다.
- sidebar와 content는 floating card가 아니라 thin separator로 구분한다.
- 외부 shell에는 `mx-auto`, `max-w-*`, 큰 outer gap, sticky viewport card 구조를 사용하지 않는다.
- 내부 card, table, toolbar, input에는 제한적으로 radius를 사용할 수 있다.
- 내부 card radius는 8px-12px 범위로 제한한다.
- button/input radius는 6px-8px 수준으로 제한한다.
- decorative radial glow와 과한 glassmorphism은 제거하거나 크게 약화한다.
- macOS vibrancy와 transparent window는 이번 범위에서 제외한다.

### 5.2 Color

필수 기준:

- window background는 거의 검정에 가까운 neutral dark이다.
- sidebar는 본문보다 아주 미세하게만 구분되는 dark neutral이다.
- 영역 구분은 배경 차이보다 low-contrast 1px separator를 우선한다.
- text는 neutral white/gray hierarchy를 사용한다.
- lime은 brand/primary action/active primary emphasis에만 사용한다.
- cyan은 informational metric 또는 chart에만 사용한다.
- green/yellow/red는 status에만 사용한다.
- active state는 색상만으로 구분하지 않는다.

### 5.3 Typography

필수 기준:

- 기본 UI font는 macOS system stack을 우선한다.

```css
-apple-system,
BlinkMacSystemFont,
"SF Pro Text",
"Helvetica Neue",
sans-serif
```

- 기존 display font는 큰 metric 숫자나 제한된 accent에만 사용한다.
- page header와 sidebar에서 지나치게 큰 compressed heading과 강한 negative letter spacing을 반복하지 않는다.
- titlebar, nav, density control, footer status는 compact하고 native하게 보이게 한다.

### 5.4 Layout And Scroll

필수 기준:

- `html`, `body`, `#root`는 full width/height이다.
- `body`는 `overflow: hidden`이다.
- `.app-shell`은 full-window grid 또는 동등한 full-window layout owner이다.
- `.window-titlebar`는 전체 width를 사용한다.
- `.app-sidebar`는 full height surface로 동작한다.
- `.app-content`만 `overflow: auto`를 가진다.
- `.page-container`가 실제 화면 content를 감싼다.
- titlebar/sidebar/body가 second scroll을 만들면 실패이다.
- minimum window size에서도 navigation과 주요 content가 사용 가능해야 한다.

### 5.5 Interaction And Accessibility

필수 기준:

- titlebar의 빈 영역은 `-webkit-app-region: drag`이다.
- button, input, select, link, nav item, density control은 `-webkit-app-region: no-drag`이다.
- traffic lights와 app name/titlebar content가 겹치지 않는다.
- keyboard `:focus-visible`이 명확하다.
- `prefers-reduced-motion`을 존중한다.
- nav/toolbar/density controls에는 hover `translateY`를 사용하지 않는다.
- hover feedback은 background, border, text color 중심이다.
- active nav는 background와 indicator, text weight, `aria-current` 등 두 개 이상의 단서로 표시한다.
- sidebar text overflow는 truncation 또는 의도된 wrapping으로 처리한다.
- disabled state contrast를 유지한다.

| File | 목적 |
|---|---|

| `src/App.tsx` | tab routing 유지 확인 |

### 6.3 Screen Cleanup Priority

화면별 파일 수정은 shell과 시각적으로 충돌할 때만 최소화한다.

우선순위:

1. Overview
2. Server Detail
3. Live Monitor
4. Process Table
5. Settings

각 화면에서 지킬 기준:

- 첫 번째 요소가 거대한 floating hero panel처럼 보이지 않게 한다.
- page header는 eyebrow/title/description/action 정도의 일반 구조로 제한한다.
- loading, error, empty, stale, backend unavailable state를 숨기지 않는다.
- API 호출, DTO rendering, state ownership은 변경하지 않는다.
- unknown metric 처리와 browser fallback identity를 유지한다.

### Phase 1: TDD Shell Contract Tests

목표: Shell refactor 전에 사용자 관점 behavior를 테스트로 고정한다.

Deliverables:

`src/components/Shell.test.tsx`에 다음 테스트를 추가/수정한다.

- Shell이 기본 `full` density로 시작한다.
- density toggle이 `compact`와 `full` 사이에서 동작한다.
- density mode는 session-only이며 `localStorage`에 저장되지 않는다.
- root `.app-shell`에 `data-density`가 적용된다.
- 모든 navigation item이 렌더링된다.
- 각 navigation item click이 `activeTab`과 `activeScreen`을 갱신한다.
- titlebar에 app name `GPUWatcher`가 표시된다.
- titlebar에 active tab label이 표시된다.
- server/online count가 표시된다.
- `overview === null`이면 count는 `unknown`이다.
- `overview === []`이면 `0 servers`, `0 online`이다.
- `online` status count는 case-insensitive로 계산된다.
- 기존 screen content children이 계속 렌더링된다.
- 가능한 한 role/label/text/aria state 기준으로 검증한다.
- private class name 검증은 root `.app-shell[data-density]` 계약에만 제한한다.

Acceptance criteria:

- 테스트가 구현 세부 DOM보다 사용자 관찰 동작을 검증한다.
- root density attribute는 명시적 계약으로 유지된다.
- refactor 후 Shell behavior regression을 잡을 수 있다.

Verification gate:

```bash
npm run test -- --run src/components/Shell.test.tsx
```

### Phase 2: Electron BrowserWindow Native Frame

목표: Electron window를 macOS native frame에 맞게 수정하되 runtime 계약은 건드리지 않는다.

Deliverables:

`electron/main.ts`에서 다음을 구현한다.

- macOS 판별 로직 추가
- `show: false` 추가
- dark window token과 맞는 `backgroundColor` 추가
- macOS에서만 `titleBarStyle: 'hiddenInset'` 적용
- 기존 size/min size 유지
- `preload-runtime.cjs` preload 유지
- `nodeIntegration: false` 유지
- `contextIsolation: true` 유지
- `mainWindow.once('ready-to-show', () => mainWindow?.show())` 추가
- `loadURL`/`loadFile` dev/package 분기 유지
- scheduler start/stop lifecycle 유지

Acceptance criteria:

- native traffic lights를 사용한다.
- custom window controls를 만들지 않는다.
- non-macOS에 불필요한 frameless behavior를 강제하지 않는다.
- preload/IPC/helper/scheduler 계약이 바뀌지 않는다.
- first paint white flash를 줄일 수 있는 show flow가 있다.

Verification gate:

```bash
npm run electron:build
```

## 9. Ultrawork Execution Notes

작업자는 다음 순서로 작은 단위 실행을 유지한다.

1. Preflight에서 현재 상태와 baseline test를 확인한다.
2. Shell behavior test를 먼저 작성하거나 구현 직전의 작은 TDD loop로 고정한다.
3. Electron window chrome 변경은 Shell/CSS 변경과 분리한다.
4. Shell structure를 먼저 semantic하게 바꾼 뒤 CSS를 적용한다.
5. CSS는 token/base/layout/components 순서로 좁게 적용한다.
6. screen cleanup은 마지막에 필요한 부분만 한다.
7. automated verification 후 Electron manual QA를 실행한다.
8. 보고서는 변경 범위, 검증 결과, manual QA 여부, residual risk를 분리해 작성한다.

병렬화 가능성:

- Phase 1 Shell tests와 Phase 2 Electron BrowserWindow 작업은 preflight 이후 병렬 진행 가능하다.
- Phase 3 이후 CSS와 screen cleanup은 순차가 안전하다. Layout이 안정되기 전 screen cleanup을 시작하지 않는다.
- Final verification은 모든 implementation phase 이후 한 번에 수행한다.

## 10. Atomic Commit Strategy

명시적으로 commit을 요청받은 경우에만 commit한다.

요청받았다면 다음처럼 원자적으로 분리한다.

1. `test(shell): cover native console shell behavior`
   - Shell density, nav, titlebar, count, children rendering tests
2. `feat(electron): use macos hidden inset window frame`
   - `electron/main.ts` BrowserWindow option과 ready-to-show flow만 포함
3. `refactor(shell): add full-window app shell structure`
   - `Shell.tsx` semantic titlebar/sidebar/content 구조
4. `style(shell): apply full-bleed console tokens and layout`
   - tokens/base/layout/components CSS
5. `style(screens): normalize page headers for desktop shell`
   - 필요한 최소 screen header cleanup
6. `test(ui): verify desktop shell refactor`
   - final test adjustment 또는 verification-only changes

Commit 시 주의사항:

- unrelated dirty changes를 stage하지 않는다.
- 실패한 verification 상태를 숨기지 않는다.
- commit message는 기존 저장소 convention을 따른다.
- commit/push는 명시적 요청 없이는 하지 않는다.

## 11. Risks And Responses

| Risk | Impact | Response |
|---|---|---|
| hiddenInset traffic lights가 content와 겹침 | titlebar usability 저하 | traffic-light reserved space와 manual QA |
| `ready-to-show` 순서 오류 | white flash 또는 blank window | handler 등록 위치 확인, Electron manual QA |
| `.app-shell` rename으로 test/CSS churn 증가 | 불필요한 regression | root 유지, semantic children 추가 |
| body와 content가 동시에 scroll | native desktop feel 실패 | body hidden, `.app-content` only scroll 검증 |
| screen cleanup 범위 확대 | 기능 regression, 일정 증가 | top header 최소 수정만 허용 |
| density를 global utility override로 유지 | layout fragility | CSS variable 기반 density로 이동 |
| active state color-only | accessibility 문제 | indicator/weight/aria-current 병행 |
| hover translate 잔존 | web dashboard 느낌 지속 | nav/toolbar/density scope에서 제거 |
| browser fallback 손상 | Vite fallback unusable | static identity와 `backend_unavailable` 확인 |
| unknown metric이 0으로 변환 | product invariant 위반 | formatter/JSX 변경 회피, screen review |
| Electron manual QA 미실행 | native frame 검증 불가 | blocker/residual risk로 보고 |
