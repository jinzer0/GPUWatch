# GPUWatcher Phase 5: Process Ledger Console 구현 계획

이 문서는 `docs/draft/draft_0006.md`를 실행 가능한 최종 계획으로 정리한 Phase 5 Process Ledger Console 작업 지시서다. `docs/plan/`과 `docs/draft/`는 역사적 계획 기록이며, 이 문서는 현재 사용자 설치 문서가 아니다.

Phase 5의 목표는 기존 `Process Table`과 `Process Detail Drawer`를 여러 서버와 GPU의 프로세스를 빠르게 비교하는 고밀도 데스크톱 process ledger로 리팩토링하는 것이다. 현재 런타임 구조는 그대로 유지한다. 앱은 macOS Electron 데스크톱 앱이고, Electron main과 preload를 통해 로컬 Rust helper를 호출하며, helper와 core가 system `ssh`로 Linux NVIDIA GPU 서버의 `nvidia-smi`, POSIX shell, `ps` 출력만 읽고, 로컬에서 protocol v1 스냅샷과 SQLite read model을 만든다.

이번 단계는 프론트엔드 화면, 프레젠테이션 모델, 접근성, 테스트, Electron 수동 QA 범위다. 백엔드, DTO, query contract, Rust helper, SQLite schema, Electron IPC, polling scheduler는 변경하지 않는다.

## 1. 작업 목표

Process Table은 다음 질문에 즉시 답해야 한다.

* 어떤 process row가 GPU memory를 가장 많이 쓰는가.
* 어느 서버와 GPU에서 실행 중인가.
* 어떤 user가 실행했는가.
* 얼마나 오래 실행 중인가.
* GPU memory, GPU util, SM util, memory util, CPU, host memory가 무엇인가.
* 현재 row인지 stale snapshot인지 구분되는가.
* parent grouped view와 user grouped view에서 관계를 잃지 않는가.
* 상세 command와 optional metric은 drawer에서 안전하게 확인되는가.

완성된 화면은 spreadsheet나 카드 대시보드가 아니라 고밀도 monitoring ledger처럼 보여야 한다. 큰 카드 모음, 일반 form strip, per-field `.surface` 카드 농장, 쓰기 액션은 금지한다.

## 2. 절대 보존할 아키텍처와 범위

다음은 Phase 5에서 건드리지 않는다.

* `ProcessRowDto`
* `listProcesses`
* `queryKeys.processes`
* React Query refetch contract
* Electron preload, IPC action contract, main process helper dispatch
* Rust helper, `gpuwatcher-core`, SSH collector, parser, repository, migration
* SQLite schema와 저장된 read model 의미
* polling scheduler와 server refresh 동작
* remote host 요구사항

원격 서버에는 GPUWatcher, nvitop, Python collector, collector package, repo 파일을 설치하지 않는다. `gpuwatcher --json`, user configurable collector command path, `collectorCommand`, `collector_command`를 활성 런타임 개념으로 되살리지 않는다.

Process Table의 Refresh는 로컬 read model을 읽는 `listProcesses` React Query refetch다. 원격 polling, scheduler 호출, server refresh, process write action, signal, kill, restart 기능을 이 화면에 추가하지 않는다.

## 3. draft 대비 변경 사항과 이유

1. 사라진 Server 또는 GPU filter는 암묵적 fallback이 아니라 명시적으로 `All`로 clear한다. 이유는 숨은 filter state가 데이터 재등장 시 사용자의 의도 없이 다시 활성화되는 문제를 막기 위해서다.
2. summary 의미를 process rows, server IDs, GPU UUIDs 기준으로 고정한다. 이유는 하나의 OS PID가 여러 GPU row로 나타날 수 있고, 이름이나 index만 세면 중복 또는 충돌을 숨기기 때문이다.
3. all-null GPU memory는 unknown으로 유지하고, known 값이 하나라도 있을 때만 known 또는 partial total로 표시한다. 이유는 null을 0으로 바꾸면 unknown metric을 실제 0 사용량으로 오해하게 만들기 때문이다.
4. group section은 label과 count만 유지한다. 이유는 group memory, util, stale aggregate가 새 null semantics와 scope semantics를 만들기 때문이다.
5. table command preview truncation은 유지하고, drawer에는 별도 sanitized non-truncating command display helper를 둔다. 이유는 table 밀도를 지키면서 drawer에서 긴 command와 secret redaction을 검증 가능하게 보여주기 위해서다.
6. 6개 primary column anatomy를 채택하되 기존 sort key는 모두 reachable하게 유지한다. 이유는 design 관점의 고밀도 ledger와 accessibility 관점의 sort reachability를 동시에 만족해야 하기 때문이다.
7. RightDrawer는 먼저 모든 consumer를 audit한다. Process detail만 production consumer라면 Phase 5에서 real modal behavior를 고친다. 여러 consumer가 있으면 shared primitive 변경을 별도 step으로 나누고 모든 consumer 테스트를 포함한다. 이유는 현재 `aria-modal` contract risk를 방치하면 접근성 오류지만, 공통 primitive를 무작정 바꾸면 다른 화면 회귀가 생기기 때문이다.
8. QA 범위를 broad visual check에서 outcome-based Electron QA로 바꾼다. 이유는 sticky header, horizontal overflow, focus trap, drawer lifecycle, density, cached-row refresh error는 unit test만으로 충분히 검증되지 않기 때문이다.
9. stale currentness는 DTO의 stale boolean만 사용한다. 이유는 latest snapshot timestamp가 현재 DTO에 없고, Phase 5에서 invented timestamp metadata를 만들면 contract scope creep가 되기 때문이다.

## 4. 핵심 UI identity와 row pipeline

`processRowKey(serverId, gpuUuid, pid)`를 canonical UI identity로 사용한다. 이 key는 React key, DOM ref, Arrow navigation, selected styling, drawer selection, refresh replacement, drawer close 후 opener focus return의 단일 기준이다. PID, object identity, array index만으로 process row를 식별하지 않는다.

Visible row pipeline은 다음 순서로 고정한다.

```text
generic filters -> exact server/GPU pair filter -> sort -> group -> focusable visible process rows
```

generic filters는 search, status, kind, stale 또는 freshness filter를 뜻한다. 그 다음 server와 GPU의 exact pair filter를 적용한다. 이후 하나의 sort state로 정렬하고, 마지막에 Flat, Parent grouped, User grouped view를 만든다. Section row는 focus target이 아니며 Arrow navigation 대상도 아니다.

현재 grouped sort behavior는 characterization test로 먼저 잠근다. Parent grouped view는 root ordering과 child PID sorting 의미를 보존한다. User grouped view는 server와 user 기준 section order를 유지하고, group 내부에서는 sorted order를 보존한다. Filtering은 grouping보다 먼저 실행되므로 parent가 숨겨져도 visible child가 승격될 수 있다. 이 동작을 UI 변경 전에 테스트로 설명하고, Phase 5에서 의미를 바꾸지 않는다.

## 5. Filter contract

Server와 GPU option은 전체 process row 데이터에서 만든 global option list를 유지한다. 현재 보이는 row만으로 option을 줄이지 않는다.

Server filter는 display name만 비교하지 않는다. 동일 server name을 가진 다른 server ID를 구분해야 한다. GPU filter도 GPU index만 비교하지 않는다. 동일 GPU index를 가진 다른 GPU UUID를 구분해야 한다.

Server와 GPU를 함께 선택하면 exact pair matching을 유지한다. 선택한 server와 선택한 GPU가 같은 process row의 pair로 존재할 때만 row가 visible하다. Cross-server mismatch는 빈 결과가 되어야 하며, 다른 서버에 같은 GPU index가 있다는 이유로 match하면 안 된다.

선택한 Server 또는 GPU option이 refresh 결과에서 사라지면 해당 filter state를 즉시 `All`로 clear한다. 사라진 option이 나중에 다시 나타나도 숨은 state가 재활성화되면 안 된다. 테스트는 disappearance, reappearance, duplicate server names, duplicate server IDs, duplicate GPU indices, duplicate GPU UUIDs, cross-server mismatch를 포함한다.

Reset은 search, server filter, GPU filter, kind filter, freshness filter, view mode, sort key, sort direction을 controller-level default state로 되돌린다.

## 6. Summary semantics

Summary helper는 pure model helper로 작성하고, 렌더링 중 반복 계산하지 않는다. Summary label은 다음 의미를 명확히 드러낸다.

* process rows: `serverId x gpuUuid x pid` 단위 row 수다. 하나의 OS PID가 여러 GPU에서 잡히면 여러 process row로 센다.
* servers: server name이 아니라 server ID 기준 unique count다.
* GPUs: GPU index가 아니라 GPU UUID 기준 unique count다.
* known GPU memory: known memory 값만 합산한다.
* partial memory: 일부 row의 memory가 null이고 일부 row만 known일 때 partial임을 label 또는 helper return으로 표현한다.
* unknown memory: 모든 visible row의 memory가 null이면 unknown이며 0으로 표시하지 않는다.

Summary는 table보다 시각적으로 커지면 안 된다. 한 줄 ledger strip 또는 compact summary text를 기본으로 한다.

## 7. Toolbar와 command strip

Toolbar는 process-specific dense command strip으로 바꾼다. 일반 form strip처럼 같은 크기의 control을 늘어놓지 않는다.

Primary strip은 Search, Server, GPU, Refresh를 포함한다. Search가 가장 넓고, placeholder는 실제 검색 대상인 PID, user, command, server를 반영한다. Refresh의 accessible name은 `Refresh process rows`처럼 명확해야 하며, pending 중 기존 table을 숨기지 않는다.

Secondary strip 또는 안전한 disclosure에는 Kind, Freshness, View, Reset을 둔다. Disclosure를 쓰면 active filter count 또는 state를 표시하고 keyboard로 열고 닫을 수 있어야 한다. Reset은 active state가 없을 때 disabled할 수 있지만, controller reset contract는 위의 전체 state를 포함해야 한다.

## 8. Table anatomy

Process ledger의 primary columns는 다음 6개다.

```text
Process | Context | User | Runtime | GPU memory | GPU util
```

Process column은 process name 또는 command preview, PID, stale 또는 current indicator를 고밀도로 담는다. Context column은 server와 GPU index를 함께 보여주고, 필요한 경우 GPU UUID는 truncate하거나 drawer로 보낸다. User, Runtime, GPU memory, GPU util은 빠른 비교가 가능해야 한다.

Secondary metric은 SM util, memory util, CPU, host memory, encoder, decoder, parent PID, GPU UUID다. 이 값들은 숨겨서 잃어버리는 것이 아니라 drawer와 table-local overflow 또는 낮은 우선순위 cell로 접근 가능하게 둔다.

금지 사항은 다음과 같다.

* 12개 column을 같은 폭과 같은 중요도로 압축하지 않는다.
* 모든 cell을 카드처럼 만들지 않는다.
* command가 table 폭을 무한히 밀지 않게 한다.
* null, unknown, `N/A`, `-` 성격의 값을 0으로 바꾸지 않는다.
* stale row를 읽기 어려운 opacity로 숨기지 않는다.

Table command preview는 기존 truncation을 유지한다. Full command는 drawer command block에서 확인한다.

## 9. Sorting reachability

Sort state는 하나만 둔다. 기존 모든 sort key는 정확히 하나의 accessible control을 통해 도달 가능해야 한다. 같은 key를 여러 control이 경쟁적으로 바꾸면 안 된다.

각 sort key는 기존 default direction을 유지한다. Numeric metric은 기본 descending, text key는 기본 ascending, 같은 control 재클릭은 asc와 desc를 toggle한다. Active sortable header 또는 control은 `aria-sort`와 visible indicator를 제공한다. 색상만으로 sort 상태를 표현하지 않는다.

Secondary sort control을 안전하게 구현하기 어렵다면 metric headers를 drawer-only로 숨기지 말고 table-local horizontal overflow 안에서 sortable header로 유지한다. 이 fallback은 shell 또는 body horizontal overflow를 만들면 안 된다.

## 10. Grouped views

Flat, Parent grouped, User grouped view mode를 모두 유지한다. Group section은 label과 process count만 표시한다. Phase 5에서는 group-level memory, utilization, stale aggregate를 추가하지 않는다.

Section row는 process row처럼 focus되지 않는다. Arrow Up과 Arrow Down은 실제 visible process row 사이에서만 이동한다. Parent indentation은 유지하되 깊은 parent tree에서도 Process column이 과도하게 밀리지 않게 한다.

Grouped view의 label과 count는 고밀도 separator나 compact section row로 표현한다. 큰 banner, 큰 card, dashboard block은 사용하지 않는다.

## 11. Drawer inspector

Process Detail Drawer는 카드 모음이 아니라 하나의 blade inspector다. 큰 accent banner와 per-field `.surface` card farm을 제거한다.

Drawer anatomy는 다음과 같다.

* sticky identity header: PID, process name, server, GPU, current 또는 stale status, close button
* compact definition rows: Identity, GPU context, host context
* grouped metrics: GPU metrics와 host metrics
* terminal-like command block: sanitized non-truncating command display
* read-only note: metadata 또는 footer로 작게 표시

Command display는 table `formatCommand` truncation을 재사용하지 않는다. 별도 helper를 만들고, secret-bearing tail marker가 있는 긴 command fixture로 실제 tail이 보이는지 테스트한다. Sanitization은 유지한다. Copy action은 Phase 5 필수가 아니며, clipboard API나 preload scope를 새로 열지 않는다.

선택한 process가 filter 또는 refresh replacement로 visible rows에서 사라지면 drawer를 닫는다. Opener row가 남아 있으면 focus를 `processRowKey(serverId, gpuUuid, pid)` ref로 돌려준다. Opener가 사라지면 table 또는 page fallback focus target으로 이동한다.

## 12. Modal과 RightDrawer accessibility 결정

구현 전 `RightDrawer` consumer를 audit한다.

Audit 결과 Process detail만 production consumer라면 Phase 5에서 drawer를 real modal로 만든다. 요구사항은 다음과 같다.

* `role="dialog"`와 적절한 accessible label을 유지한다.
* `aria-modal` contract와 실제 동작이 일치한다.
* open 시 Close button에 focus한다.
* Tab과 Shift+Tab이 drawer 내부에 containment된다.
* background table과 page interaction을 막는다.
* Escape로 닫힌다.
* close 후 opener row로 focus를 돌린다.
* opener가 사라졌으면 table 또는 page fallback으로 focus한다.

Audit 결과 다른 production consumer가 있으면 shared primitive 변경을 Phase 5 하위 step으로 분리한다. 이 경우 모든 consumer의 open, close, Escape, Tab containment, opener return 테스트를 추가하거나 갱신한 뒤 Process detail markup을 적용한다. 다른 화면 회귀가 예상되면 Process Detail 전용 wrapper로 범위를 줄이고 shared primitive remediation은 별도 후속 계획으로 남긴다.

## 13. CSS와 responsive contract

Table은 table-local horizontal overflow만 허용한다. App shell, body, page container에 horizontal scrollbar가 생기면 실패다.

Sticky header는 table scroll context 안에서 동작한다. Header background는 불투명해야 하며 body text가 비치면 안 된다. Header와 body column alignment가 horizontal scroll에서 유지되어야 한다.

Mandatory inner vertical table viewport는 만들지 않는다. 자연 page scroll을 기본으로 하고, sticky header와 drawer 내부 scroll만 신중하게 사용한다. Sticky first column은 optional이며, grouped section row, focus ring, horizontal scroll alignment를 깨뜨리지 않을 때만 허용한다.

Focus ring은 clipped 되면 안 된다. Long command, long username, long server name, long GPU UUID는 truncate, wrap, mono treatment를 각 위치에 맞게 적용한다.

Full density와 Compact density 모두 같은 정보 구조와 접근성 contract를 유지한다.

## 14. 작업 순서

1. Contract와 characterization tests를 markup 변경 전에 작성한다.
   * `processRowKey(serverId, gpuUuid, pid)`가 React key, DOM ref, navigation, selected row, drawer selection, refresh replacement, focus return의 기준임을 테스트한다.
   * Current filter, sort, grouped view, drawer close, focus return, refresh error with cached rows behavior를 characterization한다.
   * Duplicate server name, duplicate server ID, duplicate GPU index, duplicate GPU UUID, exact server/GPU pair mismatch를 잠근다.
2. Pure model과 summary helpers를 추가한다.
   * Summary count는 process rows, server IDs, GPU UUIDs 기준으로 계산한다.
   * Memory helper는 known, partial, unknown을 구분하고 all-null을 0으로 만들지 않는다.
   * Command display helper는 drawer용 sanitized non-truncating output을 제공한다.
3. Controller contract를 조정한다.
   * Pipeline 순서를 generic filters, exact server/GPU pair filter, sort, group, focusable visible process rows로 고정한다.
   * 사라진 Server 또는 GPU option은 `All`로 clear하고, reappearance가 hidden state를 되살리지 않게 한다.
   * Reset이 search, filters, view, sort key, sort direction을 default state로 되돌리게 한다.
   * 하나의 sort state와 모든 sort key reachability를 유지한다.
4. Toolbar, table, drawer DOM과 accessibility를 리팩토링한다.
   * Dense command strip, 6개 primary ledger columns, grouped section label/count, command preview truncation, drawer inspector anatomy를 적용한다.
   * Sort control의 accessible name, default direction, `aria-sort`를 보존한다.
   * RightDrawer audit 결과에 따라 modal containment 또는 consumer-safe primitive step을 구현한다.
5. Scoped CSS와 responsive work를 적용한다.
   * Table-local horizontal overflow, sticky header, focus ring, long value handling, Full과 Compact density를 조정한다.
   * Shell/body overflow, 큰 카드, generic form strip, per-field surface farm을 제거한다.
6. Test migration과 verification을 수행한다.
   * Layout-coupled serialized row assertion만 교체한다.
   * Behavior assertion은 삭제하지 않는다.
   * Pure/controller/semantic DOM/integration test 순서로 넓힌다.
7. Electron과 manual QA를 완료한다.
   * 1024x720과 1280x860에서 Full과 Compact density를 모두 확인한다.
   * Long values, horizontal overflow, sticky header, drawer lifecycle, cached-row refresh error, screenshot-reviewed ledger anatomy를 확인한다.

## 15. 테스트 계획

Pure model tests는 다음을 포함한다.

* 빈 rows
* 하나의 current row
* current와 stale 혼합
* 여러 server IDs
* 동일 server name과 다른 server ID
* 동일 GPU index와 다른 GPU UUID
* known GPU memory 합계
* partial memory와 all-null unknown memory
* `processRowKey(serverId, gpuUuid, pid)` 안정성
* drawer command helper의 sanitization, non-truncation, long secret-bearing tail marker

Controller tests는 다음을 포함한다.

* pipeline ordering
* generic filter 후 exact server/GPU pair filter
* cross-server mismatch empty result
* vanished server filter clear to `All`
* vanished GPU filter clear to `All`
* vanished option reappearance가 hidden filter state를 되살리지 않음
* Reset이 search, filters, view, sort key, sort direction을 초기화
* 모든 existing sort key reachability와 default direction
* grouped view의 current ordering behavior
* section rows가 focusable process rows에 포함되지 않음

DOM과 integration tests는 다음을 포함한다.

* page identity와 table accessible label 또는 caption
* loading, no rows, filtered empty, query error with existing rows
* text search, server filter, GPU filter, kind filter, freshness filter
* Flat, Parent grouped, User grouped mode
* default sorting, toggle sorting, numeric metric default descending
* active sort `aria-sort`
* command preview truncation in table
* full command visibility in drawer
* stale textual indicator
* row click, Enter, Space drawer open
* Arrow Up과 Arrow Down navigation
* drawer close 후 opener focus return
* opener vanishes fallback focus
* modal Tab과 Shift+Tab containment when applicable
* Escape close
* Refresh pending, success, cached-row refresh error
* Full과 Compact density에서 semantic controls 유지

테스트는 role, accessible name, visible text, focus behavior, 사용자 동작을 우선한다. Class name이나 pixel-perfect DOM snapshot에 과하게 의존하지 않는다.

## 16. 실행할 검증 명령

구현 worker는 최소 다음을 실행한다.

```bash
npm run test -- --run
npm run build
npm run electron:build
```

Rust, helper, backend 범위를 변경하지 않았어도 no-scope-creep 확인이 필요하거나 shared contract가 의심되면 다음을 추가로 실행한다.

```bash
cargo test --manifest-path crates/gpuwatcher-core/Cargo.toml
cargo test --manifest-path crates/gpuwatcher-helper/Cargo.toml
```

Electron QA 전 helper binary가 필요하면 다음을 실행한다.

```bash
npm run helper:build
npm run electron:dev
```

Live SSH ignored test는 Phase 5 기본 검증이 아니다. 사용자가 명시하거나 live target이 필요한 결함을 재현할 때만 env-gated 명령으로 실행한다.

## 17. Manual Electron QA

Manual QA는 broad `looks good`가 아니라 outcome-based로 기록한다. 최소 viewport는 1024x720과 1280x860이다. 두 viewport에서 Full density와 Compact density를 모두 확인한다.

확인 항목은 다음과 같다.

* ledger anatomy가 6개 primary column 중심으로 읽히는가.
* toolbar가 dense command strip이고 generic form strip처럼 보이지 않는가.
* summary가 process rows, server IDs, GPU UUIDs, known 또는 partial memory를 올바르게 말하는가.
* long command, long username, long server name, long GPU UUID가 shell width를 밀지 않는가.
* horizontal overflow가 table-local로만 생기는가.
* sticky header가 투명 bleed 없이 유지되는가.
* 모든 sort key가 accessible control로 reachable한가.
* grouped section row가 focus target이 아닌가.
* Arrow navigation이 visible process row만 이동하는가.
* drawer open 시 Close focus, Tab containment, Escape close, opener return이 동작하는가.
* opener row가 refresh 또는 filter로 사라지면 table 또는 page fallback focus가 동작하는가.
* cached rows가 있는 refresh error에서 기존 rows가 사라지지 않고 warning이 보이는가.
* no rows와 filtered empty가 구분되고 filtered empty Reset action이 동작하는가.
* table command preview는 truncate되고 drawer command block은 sanitized full command를 보여주는가.
* screenshot 검토에서 큰 카드, card farm, spreadsheet 압축, body horizontal overflow가 없는가.

QA 데이터는 가능한 한 다음 상태를 포함한다.

* process 1개에서 3개
* process 수십 개
* 여러 server와 GPU
* 동일 server name과 다른 server ID
* 동일 GPU index와 다른 GPU UUID
* current와 stale 혼합
* null optional metrics
* 매우 긴 command와 secret-bearing tail marker
* 매우 긴 username, server name, GPU UUID
* Flat, Parent grouped, User grouped view
* refresh pending과 refresh error with existing rows

## 18. No-go constraints

다음이 필요해 보이면 Phase 5 구현을 멈추고 별도 계획으로 분리한다.

* Backend, DTO, API, Electron IPC, Rust, database, polling scheduler 변경
* Remote install 요구사항 추가
* `gpuwatcher --json`, collector command path, `collectorCommand`, `collector_command` 재도입
* Process write action, signal, kill, restart, server refresh, polling trigger 추가
* URL state, persistence, new saved user preference 추가
* Fixed row quota
* Mandatory inner vertical table viewport
* Group memory, group utilization, group stale aggregate 추가
* DTO에 없는 latest snapshot timestamp 또는 currentness metadata 발명
* Drawer command copy action을 위해 preload나 clipboard 권한 확대
* Sort key 일부를 drawer-only 또는 hidden-only로 만들어 keyboard 사용자가 도달할 수 없게 하는 변경

## 19. Acceptance criteria

작업은 다음 조건을 모두 만족해야 완료다.

* Process Table은 고밀도 process ledger처럼 보이고, spreadsheet 또는 dashboard card wall처럼 보이지 않는다.
* Process, Context, User, Runtime, GPU memory, GPU util primary columns가 빠른 비교를 돕는다.
* Search, Server, GPU, Refresh가 dense primary command strip에 있고, Kind, Freshness, View, Reset은 안전한 secondary strip 또는 disclosure에 있다.
* `processRowKey(serverId, gpuUuid, pid)`가 모든 UI identity와 focus return 기준이다.
* Pipeline ordering은 generic filters, exact server/GPU pair filter, sort, group, focusable visible process rows다.
* 사라진 Server 또는 GPU filter는 `All`로 clear되고, 재등장해도 hidden state가 되살아나지 않는다.
* Summary는 process rows, server IDs, GPU UUIDs, known, partial, unknown memory를 정확히 표현한다.
* Group section은 label과 count만 갖고 새로운 aggregate를 만들지 않는다.
* Table command preview는 truncate되고 drawer command display는 sanitized non-truncating helper를 쓴다.
* 모든 기존 sort key는 하나의 sort state 아래 정확히 하나의 accessible control로 reachable하다.
* RightDrawer 접근성은 audit 결과에 맞게 modal contract와 실제 focus behavior가 일치한다.
* Sticky header, table-local horizontal overflow, focus ring, long values가 1024x720과 1280x860에서 안정적이다.
* Backend, DTO, API, Electron IPC, Rust, database, polling scheduler 변경이 없다.
* `npm run test -- --run`, `npm run build`, `npm run electron:build`가 통과한다.
* Manual Electron QA 결과와 screenshot-reviewed ledger anatomy가 완료 보고에 남아 있다.
